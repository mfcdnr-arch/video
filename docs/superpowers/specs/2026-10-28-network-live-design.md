# «Эфир сети»: что сейчас идёт на экранах, общий эфир, правка плейлиста

Дата: 28.10.2026 · Этап 2 переделки по замечаниям заказчика (этап 1 — плейлисты и показы по датам,
`2026-10-26-playlists-redesign-design.md`, реализован).

Макеты, согласованные с заказчиком, лежат вне репозитория:
`Video Claude/.superpowers/brainstorm/76053-1793192646/content/` — `live-network.html` (вариант A — выбран),
`live-network-v2.html` (полоса общего эфира — вариант 1, окно включения, правка плейлиста — вариант А).

Пометка **[решение разработчика описания]** — выбор, сделанный при составлении описания без прямого
подтверждения заказчика.

---

## 1. Зачем

Раздел «Эфир сети» сейчас — только рубильник: список плейлистов, клик по любому **сразу, без подтверждения**
включает его на все экраны и перекрывает любое расписание до ручного выключения. Заказчик хочет видеть,
**на каких экранах какой плейлист идёт прямо сейчас**, по клику на плейлист — сведения о нём, и оттуда же
**переходить к правке плейлиста**. Общий эфир на все экраны остаётся, но включается осознанно и может
закончиться сам.

## 2. Цели

1. Страница «Эфир сети» = обзор сети в реальном времени (вариант A): таблица экранов «что идёт сейчас».
2. Панель «О плейлисте» по клику на плейлист.
3. Правка плейлиста из панели — окном поверх страницы (вариант А).
4. Общий эфир: всегда видимая полоса (вариант 1), включение через окно подтверждения,
   длительность «до отмены» или «до заданного часа сегодня» (**подтверждено заказчиком**).
5. Файлы плейлиста общего эфира скачиваются экранами (сейчас — нет, экран мог уйти в чёрное).
6. Единое правило «в сети» (§4.5) — на новой странице и заодно в разделах «Экраны» и «Дашборд»
   (**подтверждено заказчиком**): сейчас там экран, пропавший вчера, навсегда остаётся «в сети».

## 3. Не цели

- Общий эфир на часть экранов (группу/выбор) — «общий» = вся сеть. Отправка на выбранные экраны уже есть
  («📤 Отправить на экраны», показы этапа 1).
- Живое видео с экранов. «Играет ролик» — по последнему сообщению агента (превью ролика, не трансляция).
- Вариантов B («по плейлистам») и C («стена экранов») — не делаем.
- Отдельная история включений общего эфира на этой странице — журнал операций (`audit_log`) уже есть.
- Изменение логики расписания/показов этапа 1.

## 4. Как должно работать

### 4.1. Страница «Эфир сети» (пункт меню тот же, `broadcast` в `layout.js`)

**Шапка:** «N экранов · M в сети · K не в сети · обновлено ЧЧ:ММ:СС», поле поиска (по названию экрана,
адресу — город/место, названию плейлиста; без учёта регистра и с «ё» = «е», как в этапе 1).

**Полоса общего эфира — всегда видна над таблицей:**
- выключен — серая пунктирная полоса «📡 Общий эфир выключен · Каждый экран показывает своё расписание»
  и кнопка «Включить общий эфир…»;
- включён — жёлтая полоса: «📡 Общий эфир: «<плейлист>» на всех N экранах», ниже «с ЧЧ:ММ · до ЧЧ:ММ
  (осталось X ч Y мин) · включил <кто> · расписание на это время перекрыто» (или «до отмены»), кнопки
  «Сменить плейлист» и «Выключить» (выключение — с подтверждением).

**Таблица экранов** (строка на экран, сортировка по названию **[решение разработчика описания]**):
- **Экран**: точка «в сети / не в сети», название, адрес (город, место); у отключённого — «не в сети X ч Y мин»
  вместо адреса. «В сети» — по правилу §4.5.
- **Сейчас идёт**: плашка(и) плейлиста(ов) с цветом плейлиста и источник: «по расписанию до ЧЧ:00»,
  «📅 показ до ЧЧ:00», «⇄ по очереди с «…»», «замена на дату», «📡 общий эфир до ЧЧ:ММ / до отмены»,
  «выключено (замена на дату)», «нет расписания — заглушки». Клик по плашке — панель «О плейлисте».
  Для экрана не в сети при включённом эфире — «📡 получит при подключении».
- **Играет ролик**: превью + название ролика, о котором агент сообщил последним (`screens.playing_file`
  → `media`), если экран в сети; иначе «нет связи — последний: <ролик>».
- **Дальше** (при выключенном общем эфире): что сменит текущее и с какого часа («<плейлист> с ЧЧ:00»;
  если до конца суток смены нет — «до конца дня без изменений» **[решение разработчика описания]**).
  **После эфира** (при включённом): что пойдёт, когда общий эфир закончится.
- Источник и смены считаются той же логикой приоритетов, что лента экрана и «Расписание → По датам»
  (этап 1, §4.7: эфир → замена «выключено» → показы с решениями → замена с плейлистом → шаблон).

**Обновление**: страница сама обновляет данные каждые 30 с, пока открыта и вкладка видима
**[решение разработчика описания]**; открытая панель и окна при этом не закрываются и не сбрасываются.

### 4.2. Панель «О плейлисте» (справа, по клику на плейлист)

- Название, «N роликов · M показов · м:сс», режим блока («блок 60 мин с заглушками» / «как есть»).
- **«Сейчас идёт на N экранах»** — список экранов (точка в сети, отметка «⇄ по очереди», «📡 общий эфир»).
- **Ролики** — превью, название, «×N», длительность; клик по ролику — просмотр (окно этапа 1).
- **«Где и когда идёт»** — показы этого плейлиста (как в карточке плейлиста этапа 1: экраны, даты, часы,
  статус); плюс одной строкой «в недельном расписании: N слотов» если плейлист стоит в шаблоне
  **[решение разработчика описания]**.
- Кнопки: **«✎ Изменить плейлист»** (окно правки этапа 1 поверх страницы), **«📤 Отправить на экраны»**
  (окно «Куда и когда» этапа 1), «Открыть в «Плейлистах»» не нужно (заказчик выбрал вариант А) — не делаем.
- Без права записи — панель только для чтения, без кнопок.
- Закрывается ✕ / Esc; при обновлении страницы (30 с) содержимое панели обновляется.

### 4.3. Правка плейлиста поверх страницы

- «✎ Изменить плейлист» открывает существующее окно правки (этап 1, `openPlaylistEditor({playlistId})`).
- Подсказка в окне: «Плейлист сейчас идёт на N экранах — изменения дойдут до них в течение минуты»
  (N из данных страницы; если 0 — подсказки нет) **[решение разработчика описания]**.
- После сохранения окно закрывается, таблица и панель обновляются сразу (не дожидаясь 30 с), пользователь
  остаётся в «Эфире сети». Для этого окно правки сообщает о сохранении (событие, как `placements-changed`
  у окна «Куда и когда»).

### 4.4. Общий эфир

**Окно «Включить общий эфир на все экраны»** (и «Сменить плейлист» — то же окно с текущими значениями):
- Плейлист — выбор с поиском (только плейлисты, в которых есть ролики, которые реально могут идти —
  одобренные и в сроке; пустые показываются серыми с подписью **[решение разработчика описания]**).
- **Как долго** (подтверждено заказчиком): «До отмены — выключу сам» или «До ЧЧ:00 сегодня, затем экраны
  вернутся к расписанию». Время — целые часы, позже текущего момента, не позже 24:00 (МСК).
- Предупреждение (жёлтое): «На всех N экранах будет идти только этот плейлист. Показы по датам,
  расписание и замены на это время перекрываются. K экранов сейчас не в сети — получат эфир при
  подключении.»
- Кнопки «Отмена» и «Включить на N экранах» (при смене — «Сменить плейлист»).

**Поведение:**
- Эфир перекрывает всё, как сейчас (приоритет 1 ленты экрана) — **но только там, где ему есть что играть**:
  если у плейлиста эфира на конкретном экране нет ни одного проигрываемого ролика (сняты с модерации,
  вышел срок, реклама алкоголя на площадке без алколицензии), на этом экране эфир не применяется и идёт
  дальше по приоритетам — как у показов этапа 1 (`pick_active`). Таблица показывает фактический источник;
  полоса эфира и окно включения предупреждают «на K экранах нечего играть — там идёт обычное расписание».
  **[решение разработчика описания]**
- «До ЧЧ:00»: после этого времени эфир считается выключенным — экраны сами возвращаются к расписанию,
  без участия администратора. Лента экрана отдаёт `active_until` = время окончания эфира (агент 1.3.0
  сам прекратит его и без связи); при «до отмены» `active_until` = null.
- Включение / смена / выключение вручную / окончание по времени — записи в журнале операций
  («Общий эфир включён: «…» до ЧЧ:00», «… сменён», «… выключен», «… завершён по времени»).
- Файлы плейлиста включённого эфира попадают в список скачивания экрана (`/files/list`), чтобы экран
  мог его играть; это касается и экранов, которые подключатся позже.

### 4.5. «В сети» — одно правило везде

- Экран **в сети**, если его последний сигнал (heartbeat, `screens.last_seen`) не старше **5 минут**
  (как счётчик «Онлайн» на дашборде) **[решение разработчика описания: порог]**; иначе — «не в сети
  X ч Y мин» (сколько прошло с `last_seen`). Экран без `last_seen` — «ни разу не выходил на связь».
- Сейчас раздел «Экраны» (`screens.js`) и плитки дашборда («Сейчас в эфире», «Диски») смотрят только на
  `screens.status === 'online'`, а в `offline` его никто не переводит — пропавший экран навсегда «в сети».
  **Подтверждено заказчиком:** перевести «Экраны» и эти плитки дашборда на то же правило. Порог — одна
  константа на сервере, отдаётся в API вычисленным полем (например `online: bool`, `offline_for_seconds`),
  чтобы фронт не дублировал правило.
- Пороги уведомлений (`offline_minutes` в настройках уведомлений) и кабинета рекламодателя не трогаем —
  это отдельные настройки со своим смыслом.

### 4.6. Права
- Смотреть страницу, таблицу и панель — все роли панели, у кого сейчас есть доступ к разделу
  (`get_current_admin`; рекламодатель — нет, как сейчас).
- Включать/менять/выключать эфир, править плейлист, отправлять на экраны — только с правом записи
  (`require_write` / `canWrite()`).

## 5. Ограничения проекта

- Стек тот же: FastAPI + PostgreSQL, vanilla JS (без сборки), общий модуль окон `modal.js` этапа 1,
  тёмная тема `style.css`, `esc()` для всех серверных значений.
- Новая миграция — `032_…`, идемпотентная, в списке initdb `docker-compose.yml` (для «до ЧЧ:00» нужен
  срок окончания эфира в `network_broadcast`).
- Логика «что идёт сейчас и что дальше» — одна для страницы, ленты экрана и «Расписания → По датам»
  (переиспользовать чистую логику этапа 1 в `placements_logic.py`), без второй копии правил приоритета.
- Время — МСК (наивные datetime, как в этапе 1). Агент не меняется (кроме того, что уже есть в 1.3.0).
- Никакого AI/ML; секреты только в `.env`.

## 6. Как проверить, что готово

- pytest: расчёт «сейчас/до/дальше» для экрана при каждом источнике (шаблон, показ, по очереди, замена,
  выключено, эфир до часа / до отмены, эфир истёк); эфир «до ЧЧ:00» перестаёт действовать ровно в срок;
  файлы эфира в `/files/list`; проверка окна включения (час в прошлом, 25:00, пустой плейлист).
- smoke: включить эфир на 1 час на стенде → лента своего экрана `active_source == "broadcast"`,
  `active_until` = срок; файл эфира в `/files/list`; выключить → лента вернулась. **Внимание:** эфир —
  на все экраны; smoke на боевом сервере с живыми экранами этот шаг пропускает (или только на стенде).
- pytest: правило «в сети» (порог 5 мин, нет `last_seen`) и вычисленные поля в API экранов и дашборда.
- E2E (на стенде): в «Экранах» и на дашборде экран без свежего сигнала — «не в сети»; страница открывается, таблица заполнена, клик по плейлисту → панель, «✎ Изменить» →
  окно правки → сохранить → таблица обновилась; включить эфир «до часа» → жёлтая полоса → выключить.
