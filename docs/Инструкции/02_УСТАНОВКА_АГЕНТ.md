# 02. Установка и настройка агента на мини-ПК

Агент — это набор Python-скриптов на мини-ПК под управлением Astra Linux. Он
скачивает медиа с сервера, играет их через плеер по расписанию, шлёт heartbeat,
принимает команды в реальном времени (WebSocket) и умеет обновляться сам (OTA).
Работает как systemd-сервис `ds-agent`.

---

## 1. Требования

- Мини-ПК с **Astra Linux 1.7 SE** (или совместимой), с рабочим столом (X-сессия).
- Реальный пользователь X-сессии (по умолчанию `toor`) — **не** root.
- Сетевой доступ к серверу (пинг + `http://10.0.119.100/health`).
- Папка `agent/` из проекта, **полностью** скопированная на мини-ПК.

Скрипт сам ставит зависимости: `python3`, `pip`, `venv`, плеер, `chrony`, `curl`.

### Пользователь и пароль — про автоматизацию
- **Агент работает от пользователя `toor`** (не root). Сам установщик запускается
  через `sudo` — root нужен только на время установки (пакеты, `/etc`, systemd),
  а служба `ds-agent` и плеер работают от `toor`.
- **Пароль `toor` для повседневной автоматизации НЕ нужен и хранить его нигде не
  надо.** Всё, что агент делает с привилегиями, уже беспарольно:
  - перезагрузка ПК и перезапуск службы — через правило `sudoers` **NOPASSWD**
    (только эти две команды);
  - вход в графическую сессию — через **автологин** (без пароля).
- Пароль `toor` понадобится только **один раз** — при интерактивном `sudo` в
  момент запуска `install.sh` на каждом мини-ПК.
- Для массового удалённого раската на много мини-ПК используйте **SSH-ключи**
  (а не пароль в файлах) — это безопаснее и не требует хранить секрет.

## ⚠️ Нюансы штатной Astra Linux SE (прочитать до установки)

### Автологин (обязательно — иначе чёрный экран)
**Что это.** Автологин (автоматический вход) — когда после включения компьютер
**сам, без ввода пароля** заходит на рабочий стол заданного пользователя.

**Зачем.** Плеер показывает ролики только внутри графической сессии пользователя
`toor`. Мини-ПК висит без клавиатуры/оператора — если после включения он покажет
экран входа и будет **ждать пароль**, рабочий стол не загрузится и будет
**чёрный экран**. С автологином мини-ПК после любого выключения питания или
перезагрузки **сам** заходит в сессию `toor` → агент запускает плеер → идёт
реклама. Без участия человека.

**Нюанс Astra.** `install.sh` включает автологин автоматически **только для
LightDM**. У штатной Astra менеджер входа — **fly-dm**, его скрипт настроить не
может, поэтому автологин включают **вручную один раз** (установщик об этом
предупредит).

**Как включить на fly-dm (один раз):**
1. Меню «Пуск» (Fly) → **Панель управления**.
2. **Система → «Менеджер входа в систему»** (утилита `fly-admin-dm`).
3. Включите **«Автоматический вход»**, пользователь **`toor`**, задержка **0**. Сохраните.

(Названия вкладок могут чуть отличаться по сборке Astra — суть: «автоматический
вход» для пользователя `toor`.)

> ⚠️ **Важно (проверено на пилоте):**
> - Настраивайте **только через GUI `fly-admin-dm`**. Правка файла
>   `/etc/X11/fly-dm/fly-dmrc` через `sed`/редактор на Astra **не срабатывает**.
> - **Не включайте «повторный автовход»** (`AutoLoginAgain=true`) — приветствие
>   зависает на окне обратного отсчёта («…logged in after %countdown seconds»).
> - Если галка автологина уже стоит, но не работает: снимите → Применить →
>   снова поставьте → Применить (пере-инициализация), затем перезагрузка.

**Как проверить:** перезагрузите мини-ПК. Если он **сам** дошёл до рабочего стола
и до видео **без запроса пароля** — автологин настроен верно.

### Блокировка и гашение экрана (signage-режим — обязательно)
Иначе после простоя рабочий стол уходит в **блокировку с паролем** поверх видео.
- **Блокировку экрана** `install.sh` отключает автоматически (пишет
  `~/.config/kscreenlockerrc`: `Autolock=false`). Проверить: файл существует и
  содержит `Autolock=false`. Если ставили не через `install.sh` — создайте его
  вручную (см. ниже).
- **Гашение/сон**: **Панель управления → «Управление питанием»** → профиль
  **«От сети»**: «Отключение экрана» = **Никогда**, «Спящий режим» = **Никогда**.
- Агент дополнительно раз в 5 минут отключает гашение/DPMS (`xset`) — это уже
  в коде, отдельно настраивать не нужно.

Ручное отключение блокировки (если нужно):
```bash
mkdir -p ~/.config
printf '[Daemon]\nAutolock=false\nLockOnResume=false\nTimeout=0\n' > ~/.config/kscreenlockerrc
```
Вступает в силу после перезахода сессии/перезагрузки.
- **Пакеты (mpv, chrony, python3).** Ставятся через `apt` — на мини-ПК нужен
  доступ к репозиториям Astra (при настройке интернет есть — норм). **mpv** есть в
  репозиториях Astra; если `apt` его не находит (`Unable to locate package mpv`) —
  подключите **расширенный репозиторий** Astra или поставьте из `.deb`. Проверка
  до установки: `apt-cache policy mpv`; после — `which mpv` → `/usr/bin/mpv`.
  Для изолированной сети без интернета/зеркала — заранее подготовьте `.deb`.
- **Firewall.** Между мини-ПК и сервером должны проходить исходящие к серверу:
  **80/tcp** (панель, медиа, API) и **123/udp** (NTP).
- **PARSEC / мандатный доступ Astra SE.** При высоком уровне защиты проверьте,
  что разрешены: запуск `mpv`, доступ к `/tmp/.X11-unix` и IPC-сокету
  `/tmp/ds-mpv.sock`, правило `sudoers` для reboot/restart. Это выявит приёмка
  на пилотном мини-ПК (инструкция 09).

## 2. Шаг 1. Зарегистрируйте экран и получите токен (в панели)

Токен привязывает конкретный мини-ПК к записи экрана на сервере.

1. Войдите в панель под администратором.
2. **Экраны → Добавить экран**. Задайте имя (например, «Каб. 3, вход»).
3. Задайте **тип площадки** (кнопка настроек экрана):
   *Прочее / Магазин / Магазин с алколицензией / Торговый центр / Офис*.
   > Важно для 38-ФЗ: реклама алкоголя выходит **только** на площадке
   > «Магазин с алколицензией» (ст. 21).
4. У созданного экрана скопируйте **токен** (кнопка «Скопировать токен») и
   запомните его числовой **ID** — они нужны для установки агента.

## 3. Шаг 2. Установите агент (одна команда)

На мини-ПК, из каталога с проектом (где лежит `install.sh` и папка `agent/`):

```bash
sudo bash install.sh <URL_СЕРВЕРА> <ТОКЕН> <SCREEN_ID> [ПОЛЬЗОВАТЕЛЬ]
```

Пример:

```bash
sudo bash install.sh http://10.0.119.100 abc123token 1 toor
```

Аргументы:
| # | Аргумент | Пример | Примечание |
|---|---|---|---|
| 1 | URL сервера | `http://10.0.119.100` | со схемой `http://` или `https://` |
| 2 | Токен устройства | `abc123token` | из карточки экрана |
| 3 | ID экрана | `1` | число из карточки экрана |
| 4 | Пользователь X-сессии | `toor` | необязательный, по умолчанию `toor`; **не** root |

Скрипт выполняет 10 шагов: проверка файлов → системные пакеты → директории →
Python-venv → проверка доступности сервера → создание `config.ini` → sudoers для
reboot/restart → NTP (chrony на российские серверы + сам сервер) → автологин и
X-сессия → регистрация и запуск systemd-сервиса `ds-agent`.

Куда всё ставится:
- `/opt/ds-agent` — код и `venv`; `/opt/ds-agent/media` — скачанные ролики
- `/etc/ds-agent/config.ini` — конфиг; `/etc/ds-agent/screen_id` — ID экрана
- `/var/log/ds-agent/ds-agent.log` — лог

---

## 4. Файл конфигурации `config.ini`

Генерируется установщиком в `/etc/ds-agent/config.ini`. Основные параметры
(шаблон — `agent/config.ini.example`):

```ini
[server]
host = 10.0.119.100      # адрес сервера
port = 80
token = <ТОКЕН>          # токен этого экрана

[player]
media_dir = /opt/ds-agent/media
player_bin = /usr/bin/mpv   # плеер mpv (управление через IPC-сокет)

[schedule]
poll_interval = 60           # опрос расписания, сек
heartbeat_interval = 30      # heartbeat, сек
command_poll_interval = 5    # опрос команд, сек

[sync]
sync_delay = 3               # задержка синхронного старта (> сетевой задержки)

[logging]
level = INFO
file = /var/log/ds-agent/ds-agent.log
max_bytes = 10485760
backup_count = 5
```

После правки конфига перезапустите агент: `sudo systemctl restart ds-agent`.

## 5. Шаг 3. Проверка

```bash
systemctl status ds-agent      # active (running)
journalctl -u ds-agent -f      # логи в реальном времени
tail -f /var/log/ds-agent/ds-agent.log
pgrep -a mpv                    # процесс плеера должен быть запущен
chronyc tracking               # время синхронизировано
```

В панели: экран должен стать **онлайн** на **Дашборде** / в разделе **Экраны**
в течение ~30 секунд (heartbeat).

> Полноэкранный запуск плеера на реальном железе мини-ПК нужно проверить
> вживую — это не проверялось вне Docker/браузера.

---

## 6. Обновление агента (OTA)

Агенты обновляются централизованно из панели — раздел **«Обновление агентов»**
(виден только ролям с правом записи). Агент скачивает новую версию и
перезапускается сам (`ds_ota_updater.py`).

> Для боевой сети рекомендуется поэтапный раскат по группам экранов с
> возможностью отката, чтобы плохое обновление не уронило всю сеть разом
> (в плане на этап с реальным железом).

---

## 7. Полное удаление агента

```bash
sudo systemctl stop ds-agent
sudo systemctl disable ds-agent
sudo rm -rf /opt/ds-agent /etc/ds-agent /var/log/ds-agent
sudo rm -f /etc/systemd/system/ds-agent.service
sudo systemctl daemon-reload
```

---

## Диагностика

| Симптом | Что сделать |
|---|---|
| Сервис не запустился | `systemctl status ds-agent`, `journalctl -u ds-agent -n 50` |
| Экран офлайн в панели | проверьте `ping 10.0.119.100` и `curl http://10.0.119.100/health` |
| «Invalid device token» | токен в `config.ini` не совпадает с токеном экрана в панели |
| Плеер не играет | `pgrep -a mpv`, лог `/var/log/ds-agent/ds-agent.log` |
| Время не то | `chronyc tracking`, `chronyc sources` |
| Файл агента не найден при установке | папку `agent/` скопировали не полностью |
