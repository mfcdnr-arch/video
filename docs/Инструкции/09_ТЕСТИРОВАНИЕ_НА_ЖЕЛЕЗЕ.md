# 09. Тестирование и приёмка на реальном железе

Пошаговая приёмка мини-ПК на **Astra Linux** перед вводом в эксплуатацию. Цель —
убедиться, что агент установился, плеер играет **в полный экран**, контент
скачивается и крутится по расписанию, время синхронизировано, панель видит экран
онлайн, команды и OTA доходят, а при потере сети агент восстанавливается.

Проходите по порядку и отмечайте пункты в **чек-листе приёмки** в конце. Если шаг
не прошёл — см. «Диагностику» этого шага и не переходите дальше, пока не устранено.

> Обозначения: **[сервер]** — команда на сервере; **[мини-ПК]** — на мини-ПК
> (по SSH или локально в терминале). IP сервера в примерах — `10.0.119.100`.

---

## 0. Предусловия (до выезда / до начала)
- [сервер] Сервер установлен и здоров: `bash install_server.sh` завершился с
  **✅ и 0 провалов** (self-test проверяет 7 контейнеров, БД, миграции, панель).
  Панель открывается: `http://10.0.119.100/`.
- Мини-ПК с **Astra Linux 1.7 SE**, рабочий стол (X-сессия), пользователь `toor`.
- Сеть между мини-ПК и сервером: `ping 10.0.119.100` проходит.
- На мини-ПК скопирована **полная** папка проекта (нужны `install.sh` и папка
  `agent/`).
- Готов **тестовый ролик** (короткое видео, mp4) — загрузите его в панель заранее
  (Медиатека → категория «служебный контент», чтобы не ждать модерацию), соберите
  плейлист и поставьте в расписание на ближайшее время. Либо сделаете на шаге 5.

---

## 1. Предустановочная проверка мини-ПК
[мини-ПК]
```bash
whoami                      # ожидаем: toor (или ваш пользователь X-сессии)
echo "$DISPLAY"             # ожидаем: :0 (графическая сессия активна)
ping -c2 10.0.119.100       # сервер доступен
curl -sf http://10.0.119.100/health && echo " — сервер отвечает"
```
Если `$DISPLAY` пуст — вы не в графической сессии; плеер не запустится в полный
экран. Войдите в рабочий стол под `toor`.

---

## 2. Регистрация экрана и токен (в панели)
[сервер/панель] **Экраны → Добавить экран** → имя (например, «Каб.3, вход») →
задайте **тип площадки** (для алкоголя — «Магазин с алколицензией», 38-ФЗ) →
скопируйте **токен** и запомните числовой **ID**.

---

## 3. Установка агента (с самодиагностикой)
[мини-ПК]
```bash
sudo bash install.sh http://10.0.119.100 <ТОКЕН> <SCREEN_ID> toor
```
Дождитесь итогового блока установщика. **Приёмка шага — только при `✅ ... провалено 0`.**
Установщик сам проверяет: встали ли пакеты (в т.ч. **mpv**), venv/зависимости,
запущена ли служба, есть ли `/usr/bin/mpv`, `config.ini`, `screen_id`, NTP,
доступность сервера. Полный лог — `/var/log/ds-agent-install.log`.

**Диагностика:** любой `✗` в выводе идёт с подсказкой. Частое:
- `mpv НЕ установлен` → `sudo apt-get install -y mpv` и переустановить.
- служба не active → `journalctl -u ds-agent -n 50`.

---

## 4. Полноэкранное воспроизведение (mpv) — ключевая проверка
Это то, что **не проверялось вне реального железа**. Убедитесь визуально и по логам.

[мини-ПК]
```bash
systemctl status ds-agent --no-pager   # active (running)
pgrep -a mpv                            # процесс mpv запущен
grep -i mpv /var/log/ds-agent/ds-agent.log | tail   # "Запуск mpv"
```
**Глазами на экране мини-ПК:** после появления контента видео должно занимать
**весь экран** — без рамок, панелей задач, курсора, оконных краёв.

**Диагностика:**
- Чёрный экран, `mpv` не запущен → проверьте `$DISPLAY`/`XAUTHORITY` в
  `systemctl show ds-agent -p Environment`; агент должен стартовать в graphical.target.
- Видео в окне, не на весь экран → проверьте, что запущен именно `mpv` с
  `--fullscreen` (лог), а не сторонний плеер.
- Плеер не находит файлы → см. шаг 5.

---

## 5. Скачивание медиа и воспроизведение по расписанию
Если ещё не сделали: [панель] загрузите тестовый ролик → плейлист → назначьте в
**Расписание** на этот экран на текущее время.

[мини-ПК]
```bash
ls -la /opt/ds-agent/media              # файлы скачались
tail -n 40 /var/log/ds-agent/ds-agent.log   # загрузка, старт воспроизведения
```
Ожидаем: ролик из расписания **проигрывается на экране** в назначенное время;
при нескольких роликах — идёт ротация по плейлисту (а не залипает на первом).

**Диагностика:**
- Медиа не качается → `curl -I http://10.0.119.100/media/<файл>` с мини-ПК;
  проверьте расписание/одобрение ролика (не `pending`), срок «с/по».
- Играет один ролик по кругу → это тот баг, что чинился (`--loop-playlist`);
  убедитесь, что на мини-ПК актуальный `ds_player.py`.

---

## 6. Синхронизация времени (NTP)
Критично: расписание и учёт показов — по московскому времени.
[мини-ПК]
```bash
chronyc tracking            # смотрите "System time" offset — секунды/мс
chronyc sources             # виден сервер 10.0.119.100 и/или ВНИИФТРИ/MSK-IX
```
Приёмка: смещение системного времени — небольшое (доли секунды), источник
синхронизирован. Если только что установили — подождите 1–2 минуты.

---

## 7. Онлайн и heartbeat в панели
[панель] На **Дашборде** / в разделе **Экраны** этот экран должен стать
**онлайн** в течение ~30 секунд и показывать актуальный статус (что играет,
свободное место). Обновление статуса идёт каждые ~30 c (heartbeat).

**Диагностика:** офлайн при живом агенте → `curl http://10.0.119.100/health` с
мини-ПК; проверьте, что токен в `/etc/ds-agent/config.ini` совпадает с токеном
экрана в панели (`Invalid device token` в логах агента).

---

## 8. Команды в реальном времени (WebSocket)
[панель] На экране в разделе **Экраны** нажмите **«Перезапустить агент»**.
Ожидаем: агент перезапустится в течение пары секунд (быстрее, чем интервал
опроса — доставка через WebSocket).
[мини-ПК] проверить:
```bash
journalctl -u ds-agent -n 20    # видно перезапуск
```
Аналогично проверьте команду **«Перезагрузка»** (перезагрузит мини-ПК; выполняйте,
если это приемлемо на площадке). Обе привилегированные операции работают
**беспарольно** (правило sudoers NOPASSWD).

---

## 9. OTA-обновление агента
Проверяем централизованное обновление по воздуху (см. [07_ОБНОВЛЕНИЕ_АГЕНТА.md](07_ОБНОВЛЕНИЕ_АГЕНТА.md)).
[панель] **Обновление агентов** → загрузите любой из 7 модулей (можно тот же
файл, с бампнутой версией/changelog) → отправьте **на этот один экран**.
[мини-ПК]
```bash
grep -i 'OTA' /var/log/ds-agent/ds-agent.log | tail
```
Ожидаем строки `OTA: <файл> проверен ✓`, `OTA: обновление ... установлено успешно`,
затем перезапуск службы. Экран возвращается онлайн.

**Диагностика:** битый файл/несовпадение MD5/синтаксическая ошибка → агент
**сам откатывается** (`OTA rollback: ...`) и остаётся на прежней версии — это
штатное защитное поведение, экран должен продолжить работу.

---

## 10. Поведение при потере сети и восстановление
[мини-ПК] Имитируйте обрыв связи с сервером (например, отключите сетевой кабель
или заблокируйте доступ):
- **Воспроизведение НЕ должно останавливаться** — уже скачанный контент
  продолжает играть из `/opt/ds-agent/media`.
- В панели экран уйдёт в **офлайн** (нет heartbeat) — ожидаемо.

Верните сеть:
- Экран снова становится **онлайн** в течение ~30 c без ручного вмешательства.
- Новые команды/расписание/OTA подхватываются.
```bash
journalctl -u ds-agent -f       # видно восстановление соединения
```
Приёмка: сеть пропала → картинка идёт; сеть вернулась → онлайн и синхронизация
восстановились сами.

---

## 11. (Опционально) systemd watchdog — только после доработки кода
Watchdog умеет перезапускать **зависший** агент. Он **выключен намеренно**.

> ⚠️ **Не раскомментируйте `WatchdogSec` в `ds-agent.service` просто так.** Пока
> агент не шлёт `sd_notify("WATCHDOG=1")` в главном цикле, systemd будет считать
> его «зависшим» и **перезапускать каждые 60 c**. Сначала нужно добавить
> отправку `WATCHDOG=1` в `ds_agent.py`, и только потом включать
> `WatchdogSec=60s` + `NotifyAccess=main`. До этого — оставить выключенным.

Если решите активировать — это отдельная доработка кода + повторная проверка
этого мини-ПК (агент под нагрузкой не должен ложно срабатывать по watchdog).

Экран: __________________   ID: ______   Дата: __________   Принял: __________

- [ ] 0. Сервер здоров, панель открывается
- [ ] 1. Мини-ПК: `toor`, `$DISPLAY=:0`, сервер пингуется

- [ ] 3. `install.sh` завершился с ✅ (0 провалов), лог сохранён
- [ ] 4. **mpv играет в ПОЛНЫЙ экран** (проверено глазами)
- [ ] 5. Медиа скачалось и крутится по расписанию (ротация плейлиста ок)
- [ ] 6. NTP синхронизирован, смещение малое

## Массовый раскат (после приёмки первого мини-ПК)
Отработав процедуру на одном устройстве, остальные ставьте так же. Для многих
мини-ПК автоматизируйте запуск `install.sh` по **SSH-ключам** (не по паролю).
OTA-обновления после этого раскатывайте **поэтапно по экранам** (см.
[07_ОБНОВЛЕНИЕ_АГЕНТА.md](07_ОБНОВЛЕНИЕ_АГЕНТА.md)): сначала 1–2 пилотных, затем
остальные.
