# 01. Установка и настройка сервера

Сервер — это Docker-стек из 7 контейнеров: PostgreSQL, Redis, MinIO (хранилище
медиа), API (FastAPI), Celery (фоновые задачи), Nginx (веб-панель на порту 80),
NTP (раздаёт точное время мини-ПК). Ставится одной командой.

---

## 1. Требования

- 64-битный Linux-сервер (или ВМ) с доступом по SSH.
- **Docker Engine** и **Docker Compose v2** (команда `docker compose`, не `docker-compose`).
  Проверка: `docker --version` и `docker compose version`.
- Открытый порт **80** (веб-панель и API для агентов).
- Желательно — выход в интернет для синхронизации времени с российскими
  серверами (ВНИИФТРИ, MSK-IX). В изолированной сети время раздаёт сам сервер.
- Свободное место под медиа и БД (том MinIO + том Postgres).

Если Docker не установлен: https://docs.docker.com/engine/install/

---

## 2. Установка (одна команда)

Из каталога проекта:

```bash
cd Video_miniPC_v16.2_modular
bash install_server.sh
```

Скрипт `install_server.sh`:
1. Проверяет Docker и Compose v2.
2. Создаёт `.env` со **случайными** секретами: пароль БД, пароль MinIO,
   `SECRET_KEY` для подписи токенов входа.
   > **Существующий `.env` никогда не перезаписывается** — при повторном запуске
   > (обновлении) пароли и ключи сохраняются.
3. Собирает и поднимает стек: `docker compose up -d --build`.
   Миграции БД (`001`–`018`) применяются автоматически при первом старте Postgres.
4. Ждёт готовности API и печатает адрес панели.

По окончании увидите:
```
Панель:  http://<IP-сервера>/
Вход:    admin / admin123
```

> Только сгенерировать `.env` без запуска стека: `bash install_server.sh --env-only`.

---

## 3. Первый вход и смена пароля администратора ⚠️

1. Откройте в браузере `http://<IP-сервера>/`.
2. Войдите: **admin / admin123**.
3. **Сразу** смените пароль: **Настройки → Пользователи → admin → Сменить пароль**.

Стандартный пароль `admin123` в проде недопустим — это первое, что нужно сделать.

---

## 4. Файл `.env`

Лежит в корне проекта, права `600`, генерируется установщиком. Содержит:

```
POSTGRES_DB=display_system
POSTGRES_USER=display_user
DB_PASSWORD=<случайный>
MINIO_USER=<...>
MINIO_PASSWORD=<случайный>
SECRET_KEY=<случайный, 64 hex>
```

- **Не публикуйте** этот файл и **не копируйте** его между серверами.
- `SECRET_KEY` подписывает токены входа — при его смене все текущие сессии
  разлогинятся.
- Каждая **новая** миграция БД должна быть добавлена в список `initdb` в
  `docker-compose.yml`, иначе на свежей установке она не применится.

---

## 5. Проверка после установки

```bash
cd Video_miniPC_v16.2_modular
docker compose ps                    # все 7 контейнеров: running
curl http://localhost/health         # 200 OK
docker exec ds_ntp chronyc sources   # NTP видит серверы времени
```

Затем откройте панель `http://<IP-сервера>/` и войдите.

---

## 6. Настройка MAX-уведомлений (необязательно)

Система умеет слать тревоги (экран офлайн, мало места, нерабочий ролик) в
мессенджер MAX. Настраивается в панели, код не трогаем.

**Настройки → Уведомления:**
1. Включите «Уведомления включены».
2. Впишите **токен бота** и **адрес** (endpoint API MAX).
3. Задайте порог «Экран офлайн дольше (мин)».
4. Отметьте, какие события слать: *Экран офлайн*, *Мало места*, *Нерабочий ролик*.
5. **Сохранить** → **Отправить тест** (придёт тестовое сообщение).

> Заголовок авторизации к API MAX — `Authorization` **без** префикса `Bearer`
> (сверено с офиц. документацией MAX).

---

## 7. Точное время (NTP)

Контейнер `ds_ntp` (chrony) синхронизируется с российскими эталонами времени и
сам раздаёт время мини-ПК. Это важно: расписание и отчёты по показам считаются
по **московскому времени**, экраны должны идти секунда-в-секунду.

Проверка: `docker exec ds_ntp chronyc sources` и `... chronyc tracking`.

---

## 8. Бэкапы и восстановление

Автобэкапы БД и медиа (MinIO) выполняет Celery по расписанию; архивы — в `backups/`.
Порядок **восстановления** из бэкапа подробно описан в
[../RESTORE_GUIDE.md](../RESTORE_GUIDE.md) — процедура проверена.

Разовый ручной бэкап и управление — через **Настройки** и раздел бэкапов в панели.

---

## 9. Обновление сервера

Повторный запуск установщика безопасно пересобирает контейнеры, сохраняя `.env`,
БД и медиа:

```bash
cd Video_miniPC_v16.2_modular
git pull            # если репозиторий под git
bash install_server.sh
```

---

## 10. Полное удаление

> **⚠️ `-v` удаляет тома с БД и медиа безвозвратно.** Сначала сделайте бэкап.
> Подробно — в [../CLEANUP_FULL_2026-07-01.md](../CLEANUP_FULL_2026-07-01.md).

```bash
docker compose down -v
```

## Диагностика

| Симптом | Что сделать |
|---|---|
| API не поднялся | `docker compose logs api` |
| Контейнер не `running` | `docker compose ps`, затем `docker compose logs <имя>` |
| Панель не открывается | проверьте порт 80 и `docker compose logs nginx` |
| Время «плывёт» | `docker exec ds_ntp chronyc tracking` |
| Забыли пароль admin | смена — через пользователя-`superadmin` в разделе Пользователи |
