# 07. Обновление агента (мини-ПК)

Агенты обновляются **централизованно из панели** по воздуху (OTA): загрузили новую
версию модулей — разослали на экраны. Заходить по SSH на каждый мини-ПК не нужно.
Раздел панели — **«Обновление агентов»** (виден только ролям с правом записи:
администратор).

---

## Как это работает (кратко)
1. Администратор загружает новые файлы агента в панель.
2. Выбирает экраны (все или часть) и жмёт «Отправить».
3. Каждому выбранному экрану ставится команда `update_agent`.
4. Агент на мини-ПК: **скачивает** файлы → **проверяет контрольную сумму (MD5)**
   → **проверяет синтаксис Python** → делает **резервную копию** текущих файлов →
   заменяет → **перезапускается** через systemd.
5. Если на любом шаге ошибка (битый файл, синтаксис, обрыв) — агент
   **автоматически откатывается** к резервной копии и остаётся работать на старой
   версии.

> Резервные копии хранятся на мини-ПК в `/opt/ds-agent/.backup/<timestamp>/`.

---

## Какие файлы можно обновлять по OTA
Только эти 7 основных модулей агента:
`ds_agent.py`, `ds_player.py`, `ds_sync.py`, `ds_heartbeat.py`, `ds_downloader.py`,
`ds_cleanup.py`, `ds_ws_client.py`.

**Нельзя обновить по OTA** (нужна переустановка через `install.sh`, см. ниже):
- сам модуль обновления `ds_ota_updater.py`;
- системные зависимости — плеер **mpv**, Python-пакеты (`requirements.txt`);
- конфиг `config.ini`, systemd-юнит, NTP.

---

## Пошагово: раскатить обновление
1. Откройте **«Обновление агентов»**.
2. **Загрузите** изменённые `.py` (кнопка загрузки файла). Панель покажет размер и
   MD5 каждого — убедитесь, что загрузились нужные.
3. Укажите **версию** и **changelog** (описание изменений) — попадут в историю и
   журнал, помогают понять, что и когда раскатывали.
4. **Выберите экраны:**
   - **Поэтапно (рекомендуется):** сначала 1–2 «пилотных» экрана.
   - либо все сразу (для мелких проверенных правок).
   > Выбор идёт **по отдельным экранам** (галочки). Отдельной кнопки «раскатить на
   > группу» пока нет — чтобы обновить группу, отметьте вручную входящие в неё
   > экраны. Автоматический групповой раскат с откатом — в плане (см. раздел ниже).
5. Нажмите **«Отправить»**.
6. Дождитесь, пока пилотные экраны обновятся и вернутся **онлайн** на Дашборде,
   проверьте, что воспроизведение идёт нормально.
7. Убедившись, что всё хорошо, повторите шаг 4–5 для **остальных** экранов.

> **Поэтапный раскат — это и есть защита сети.** Не отправляйте непроверенное
> обновление сразу на все экраны: битую правку легче заметить на двух экранах,
> чем откатывать всю сеть.

---

## Проверка после обновления
На Дашборде / в разделе «Экраны»:
- экран вернулся **онлайн** (heartbeat) в течение ~1 минуты после команды;
- играет ожидаемый контент.

На мини-ПК (если есть доступ):
```bash
journalctl -u ds-agent -n 50           # ищите строки "OTA: ... установлен", "перезапуск"
tail -n 50 /var/log/ds-agent/ds-agent.log
pgrep -a mpv                            # плеер запущен
```
В логе успешного OTA будут строки вида `OTA: <файл> проверен ✓`,
`OTA: обновление vX установлено успешно`. При откате — `OTA rollback: ...`.

---

## Если что-то пошло не так
- **Экран не вернулся онлайн после обновления.** Проверьте `journalctl -u ds-agent`.
  Агент при ошибке откатывается сам; если завис — перезапустите:
  `sudo systemctl restart ds-agent`.
- **Нужно вернуть предыдущую версию вручную.** Резервные копии — в
  `/opt/ds-agent/.backup/`; скопируйте файлы из последней папки обратно в
  `/opt/ds-agent/` и `sudo systemctl restart ds-agent`.
- **Обновление не применяется / нужно обновить `ds_ota_updater.py` или mpv/пакеты.**
  Это OTA не умеет — переустановите агент из свежей папки `agent/`:
  ```bash
  sudo bash install.sh http://10.0.119.100 <ТОКЕН> <SCREEN_ID> <пользователь>
  ```
  (см. [02_УСТАНОВКА_АГЕНТ.md](02_УСТАНОВКА_АГЕНТ.md)). Переустановка сохраняет
  зарегистрированный экран (токен/ID те же).

---

## Поэтапный раскат на всю сеть (по группам) — процедура на железе
На реальной сети агент **нельзя** обновлять сразу на все экраны — плохая версия
уронит всю сеть разом. Раскат ведём **волнами по группам**, с контролем между
волнами. Пока групповой таргетинг не автоматизирован, процедура выполняется
вручную (выбором экранов группы), но порядок действий — тот же.

**Волны раската:**
1. **Пилот** — 1–2 экрана (лучше физически доступных). Отправить обновление,
   дождаться возврата онлайн и проверить воспроизведение **вживую**.
2. **Малая группа** — одна группа/зона экранов. Отметить её экраны, отправить,
   проконтролировать на **Дашборде**.
3. **Остальные группы** — по одной, с паузой между волнами.

**Контроль между волнами (критерии СТОП):**
- Все экраны волны вернулись **онлайн** в течение ~1–2 минут и **играют** контент.
- Если после волны хоть один экран **не вернулся** онлайн или не играет —
  **СТОП**, дальше не раскатываем, пока не разобрались.
- Ориентир порога: уход в офлайн **> ~10–20 %** экранов волны — признак плохой
  версии; немедленно откат.

**Откат (если волна прошла плохо):**
- Раскатать **предыдущую заведомо рабочую версию** тем же способом на затронутые
  экраны; либо на конкретном мини-ПК восстановить из `/opt/ds-agent/.backup/`
  (агент и сам откатывается при ошибке проверки — см. выше).
- Полный откат мини-ПК — переустановка из проверенной папки `agent/`
  (см. [02_УСТАНОВКА_АГЕНТ.md](02_УСТАНОВКА_АГЕНТ.md)).

**Что планируется автоматизировать (замечание З-05, этап железа):**
- выбор **группы** экранов одним действием в разделе «Обновление агентов»;
- **автоматическая приостановка** раската, если доля офлайн-экранов превысила
  порог, с уведомлением оператора;
- фиксация «эталонной» предыдущей версии для **быстрого автоотката** на сеть.
До внедрения — пользуйтесь ручной волновой процедурой выше.

## Хорошие практики
- Перед раскатом на сеть — прогнать новую версию агента на **одном** мини-ПК.
- Всегда заполнять **версию и changelog** — это ваша история изменений.
- Раскатывать в **непиковое время** (обновление = короткий перезапуск плеера).
- Держать проверенную папку `agent/` под рукой на случай полной переустановки.
