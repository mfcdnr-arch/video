# 10. План проверки работоспособности всех функций (развёрнутая система)

Полная функциональная приёмка на **боевом контуре**: сервер `10.0.119.100` +
пилотный мини-ПК. Порядок этапов важен — каждый следующий опирается на
предыдущий. В каждом пункте: *действие → ожидаемый результат*. Отмечайте
чек-боксы; если результат другой — фиксируйте и смотрите
[runbook](../Техдокументация/03_RUNBOOK_ИНЦИДЕНТЫ.md).

Приоритеты: **P0** — без этого система не работает; **P1** — важные функции;
**P2** — дополнительные/разовые проверки.

> ✅ — уже проверено на пилоте 27.07.2026 (при повторной приёмке можно
> перепроверить быстро).

---

## Этап 0. Инфраструктура сервера (P0, ~15 мин)

- [x] ✅ **Самодиагностика**: Настройки → Диагностика сервера → «Запустить
  проверку» → **все пункты зелёные** (БД, миграции — применены все файлы
  `001`…`034`, Redis, Celery, MinIO, NTP, диски, свежесть бэкапа). Отметка ✅ —
  с приёмки 27.07, когда миграций было 26; после обновления сервера
  перепроверьте.
- [ ] **selfheal с хоста**: `bash selfheal.sh --dry-run` → «Все проверки
  пройдены», код возврата 0.
- [ ] **Smoke-тест** (неразрушающий, создаёт и удаляет своё):
  «ИТОГ: пройдено 170, провалено 0» (актуальные числа — в
  [04_ТЕСТЫ](../Техдокументация/04_ТЕСТЫ.md), §2). На боевом сервере
  `SMOKE_ALLOW_BROADCAST` **не задавать**: шаг общего эфира идёт на все
  экраны (со флагом, на стенде, итог — 198 и 0 провалов). На боевом сервере
  пароль admin сменён — передайте его через переменную (ввод скрытый, в
  историю не попадает):
  ```bash
  read -rsp "Пароль admin: " ADMIN_PASS; echo; ADMIN_PASS="$ADMIN_PASS" bash smoke_test.sh; unset ADMIN_PASS
  ```
- [ ] **Бэкап вручную**: Настройки → «Создать бэкап сейчас» → файл появился в
  списке; авто-бэкап моложе 26 ч (это же видит самодиагностика).
- [ ] **Бэкап только по входу**: «Скачать» в панели сохраняет `backup_….sql.gz`;
  прямой запрос без входа — отказ (с любого компьютера сети):
  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' http://10.0.119.100/api/backups/1/download
  curl -s -o /dev/null -w '%{http_code}\n' http://10.0.119.100/api/diagnostics/1/download
  ```
  Оба — `401`, и номер не важен: без входа сервер не говорит даже, есть ли
  такой файл (не `200` и не `404`).
- [ ] **NTP**: `docker exec ds_ntp chronyc tracking` → источник выбран; в
  разделе «Экраны» разница часов мини-ПК ≈ 0–2 с.

## Этап 1. Доступ и роли (P0, ~15 мин)

- [x] ✅ Вход `admin`; при первом входе со стандартным паролем — принудительная
  смена.
- [ ] Создать тестовых пользователей (Настройки → Пользователи, под
  `superadmin`): **аудитор** и **модератор**.
- [ ] Вход **аудитором**: видит дашборд/отчёты/журнал, **нет** кнопок

- [ ] Вход **модератором**: работает только «Модерация» (одобрить/отклонить);

- [ ] **Блокировка**: заблокировать тестового пользователя → вход отклоняется;
  разблокировать → вход работает.
- [ ] Отчёт «Входы пользователей в панель» показывает эти входы.

## Этап 2. Медиатека (P0, ~30 мин)

- [ ] **Загрузка рекламного ролика** (реальный MP4 H.264 ≤1080p): категория
  например «Продукты», маркировка 0+ → статус «на модерации», в эфир не идёт.
- [ ] **Баннер** JPG/PNG с длительностью 15 с → принят, в карточке «15 с».
- [ ] **Служебный ролик** (категория «Служебный контент») → сразу `approved`.
- [ ] **Заглушки**: Медиатека → Заглушки → «Загрузить заглушки» (3–5 роликов
  суммарно ≥ 5 мин) → итог «N шт · время» совпадает.
- [ ] **Общая медиатека**: создать папку, загрузить файл в неё, переложить файл
  между папками селектом на карточке.
- [ ] **Запреты**: попытка загрузить с категорией «табак» → загрузка отклонена.
- [ ] **Битый файл** (например, переименованный .txt в .mp4) → отклонён
  проверкой, в медиатеку не попал.
- [ ] **Поиск** сверху находит ролик по названию/рекламодателю; миниатюры
  отображаются.
- [ ] Цена рекламодателя ₽/мин сохраняется (понадобится в этапе 8).

- [ ] Создать плейлист → по умолчанию бейдж **«блок 60 мин»**.
- [ ] Добавление ролика — **выбор «папка → ролик»**; добавить одобренный ролик.
- [ ] Панель блока: «Основные … Заглушками добавится … Итого ≤ 60 мин»;

  «заглушек нет», после — «будут повторяться» или без предупреждений).
- [ ] **Дубль**: повторное добавление того же ролика → отказ с пояснением.
- [ ] Добавить этот же ролик во второй плейлист → предупреждение «уже
  используется в …».
- [ ] Переключить в **произвольный** режим и обратно; сменить целевую
  длительность (например 30 мин) → расчёт пересчитался.

## Этап 5. Расписание и эфир на экране (P0, ~30 мин + наблюдение)

- [ ] Назначить плейлист на **текущий час** пилотного экрана → мини-ПК начал
  играть в течение ~1 минуты.
- [x] ✅ На физическом экране: **mpv во весь экран**, без рамок/панелей/курсора.
- [ ] **Заглушки в эфире**: заставки идут **между** основными роликами
  равномерно, блок не превышает целевую длительность.
- [ ] **🔎 Симулятор** на этот час совпадает с тем, что реально играет.
- [ ] **Переопределение даты** (календарь месяца) на завтра → слот виден;
  «Сбросить переопределения месяца» возвращает шаблон.
- [ ] **⧉ Скопировать расписание экрана** (можно на тот же экран-группу) —
  слоты продублировались.
- [ ] **Уровни**: назначить слот на **группу** → экран играет его там, где нет
  своего слота; слот **экрана** перебивает групповой.
- [ ] **Эфир сети**: в таблице у каждого экрана видно, что идёт сейчас, ролик
  и «Дальше»; клик по плашке открывает панель «О плейлисте»; «✎ Изменить
  плейлист» открывается поверх страницы.
- [ ] **Общий эфир**: «Включить общий эфир…» → плейлист, «до ЧЧ:00» или «до
  отмены» → экран переключился, полоса жёлтая; «Выключить» → вернулось
  расписание; «до ЧЧ:00» кончается само в назначенный час (запись «Общий эфир
  завершён по времени» в журнале).
- [ ] **Эфир сети: автообновление** (E2E его не ждёт — проверка ручная): оставьте
  страницу открытой и не трогайте ~1 минуту → время «обновлено ЧЧ:ММ:СС» в шапке
  меняется примерно раз в 30 с; введённый в поиск текст и открытая панель
  «О плейлисте» при этом остаются на месте.
- [ ] **Эфир сети: ошибка и «Повторить»**: в инструментах разработчика браузера
  (вкладка «Сеть») включите режим «Офлайн» и подождите до 30 с → над таблицей
  красная строка «Не удалось обновить данные… Показаны данные на ЧЧ:ММ:СС» и
  кнопка **«Повторить»**, таблица не пропала; снимите «Офлайн», нажмите
  «Повторить» → строка исчезла, время в шапке обновилось.
- [ ] **Эфир сети: «нечего играть» — до включения** (нужен плейлист только с
  рекламой алкоголя и экран без типа площадки «Магазин с алколицензией»):
  «Включить общий эфир…» → выберите этот плейлист → в жёлтом предупреждении
  «На K экранах нечего играть — там идёт обычное расписание»; если так на всех
  экранах — «Эфир ничего не перекроет», а кнопка называется просто «Включить»
  (без «на N экранах»). Окно можно закрыть «Отмена» — включать эфир для этой
  проверки не нужно.
- [ ] **Эфир сети: «нечего играть» — если включить** (то же, но эфир включён;
  он идёт на ВСЕ экраны сети, где ему есть что играть, поэтому проверяйте
  на стенде или в нерабочее время): у такого экрана в таблице
  пометка «📡 общий эфир на этом экране не идёт — нечего играть», идёт его
  обычное расписание, а в последней колонке (заголовок «После эфира») — его
  ближайшая смена («… с ЧЧ:00» или «до конца дня без изменений»); на
  остальных экранах эфир идёт. «Выключить» — экраны вернулись
  к расписанию в течение минуты.
- [ ] **Эфир сети: «не в сети X мин»**: выключите питание пилотного мини-ПК (или
  остановите `ds-agent`) и подождите ~6 минут → у экрана серая точка и подпись
  «не в сети 6 мин» вместо адреса, в шапке «K не в сети» выросло на 1, то же
  самое в «Экранах» и на Дашборде; включите обратно → в течение минуты экран
  снова «в сети».
- [ ] **Массовое удаление**: галочками удалить выбранные слоты; «очистить
  день» кликом по дню.
- [ ] Ролик с истекающим сроком «по» → после срока пропадает из эфира
  (видно в симуляторе; плитка «Истекают ≤3 дней» на дашборде).

## Этап 6. Управление экраном (P0/P1, ~50 мин)

- [x] ✅ **■ Стоп** → показ остановился; **▶ Показ** → возобновился (без
  перезапуска агента).
- [ ] **Бегущая строка — «срочные объявления»** (P0; нужен агент ≥1.4.0).
  Раздел переделан: прежняя отметка ✅ с пилота 27.07 относилась к старой
  странице и здесь не засчитывается. Пункты, помеченные «🖥», проверяются
  **только на реальном мини-ПК** (в Docker проверена серверная часть —
  `smoke_test.sh` и `ui_test.sh`, строку на экране они не видят):
  - [ ] 🖥 **Из шаблона на все экраны.** «Магазин закрывается через 15 минут…» →
    «▶ Запустить на N экранах» → за ~5 с строка бежит у нижнего края; в «Сейчас
    идут» — «на всех N экранах», «ещё 15 мин», «запустил <вы>». Через 15 минут
    она исчезла сама, в журнале — «Бегущая строка снята по сроку».
  - [ ] 🖥 **«До снятия» на группу + перезагрузка.** «Где» → «Группы» → группа →
    «До снятия» → строка бежит на экранах группы. Перезагрузить мини-ПК — после
    старта агента строка снова бежит.
  - [ ] 🖥 **Смена плейлиста строку не трогает.** Сменился часовой слот или
    показ на одном экране (или включили общий эфир) — строки на всех экранах
    продолжают идти.
  - [ ] 🖥 **Две строки на одном экране** бегут по очереди; «Снять» одну — вторая
    продолжает.
  - [ ] 🖥 **«Стоп» не снимает строку.** «■ Стоп» на экране A → на A строки нет, на
    экране B бежит; «▶ Показ» на A → строка вернулась, если срок не вышел.
  - [ ] 🖥 **«✎ Изменить».** Поправить текст идущей строки → через секунды на
    экране новый текст; срок остался прежним; в журнале — «Бегущая строка
    изменена».
  - [ ] 🖥 **Экран был выключен при запуске.** Запустить строку на выключенный
    мини-ПК, включить позже (срок не вышел) → строка появилась.
  - [ ] 🖥 **Старый агент (1.3.0).** Экран со старым агентом показывает новую
    строку по-старому (командой); в панели у него «старый агент — без
    подтверждения».
  - [ ] 🖥 **«Бежит на X из N».** Через ~30–40 с после запуска в «Сейчас идут» —
    «бежит на N из N». «Стоп» на экране A → «на N−1 из N», у A причина
    «остановлен («Стоп»)». Мини-ПК выключили — через ~5 минут причина «не в
    сети X мин — получит при подключении».
  - [ ] **Smoke и E2E не выводят строку на реальные экраны.** `smoke_test.sh` и
    `ui_test.sh` запускают строки только на своём тестовом экране (цель
    «Экраны»: `SMOKE_…` / `E2E_стенд_…`); строка «на все экраны» бывает только в
    `ui_test.sh` при `E2E_ALLOW_BROADCAST=1`, а эту переменную (как и
    `SMOKE_ALLOW_BROADCAST`) на боевом не задают. Проверка: во время
    `smoke_test.sh` в «Сейчас идут» строка `SMOKE_tk_…` идёт на один экран
    (`SMOKE_…`), на реальных экранах её нет.
- [ ] **↺ Агент** (перезапуск) → экран вернулся онлайн ≤1 мин, эфир
  продолжился.
- [ ] **Громкость день/ночь**: изменить → звук на экране изменился по времени
  суток.
- [ ] **Питание монитора** (P1, вечерний тест): задать окно ⏻ → монитор
  выключился/включился по расписанию.
- [ ] **Синхростарт** (P2 — когда появится второй экран): два экрана стартуют
  ролик синхронно.
- [ ] **Телеметрия экрана** на карточке актуальна: свободный диск, версии
  ОС/плеера, разница часов, «что играет» (heartbeat ~30 с).
- [ ] **📺 Контроль монитора** (V2, нужен агент ≥1.2.0): бейдж у экрана зелёный.
  Выдернуть кабель HDMI → в течение ~1 мин бейдж стал красным, под карточкой
  строка «⚠ Монитор отключён от видеовыхода», на Дашборде — блок «Монитор не
  подключён»; через 3 мин пришло уведомление в MAX. Вернуть кабель → бейдж
  зелёный, в MAX сообщение «монитор снова подключён».
  Если бейдж остался серым — драйвер не отдаёт статус, снимите с мини-ПК
  вывод `grep -H . /sys/class/drm/*/status` и приложите к отчёту приёмки.
- [ ] **🧾 Диагностика** (нужен агент ≥1.1.2): нажать кнопку → через ~30 с
  в списке под экраном появился архив → скачивается и открывается
  (внутри journalctl, лог агента, конфиг без токена, версии, диск, плеер,
  часы).

## Этап 9. Отказоустойчивость — управляемые сбои (P0, ~1 час)

> Делать в согласованное время; это главная ценность приёмки.

- [ ] **Обрыв сети мини-ПК** (вынуть кабель на 10 мин): экран продолжает
  играть скачанный контент **автономно**; на дашборде — офлайн; вернуть сеть →
  экран онлайн, в отчёте «Потери связи» появилась запись с длительностью.

## Сводка трудозатрат

| Этапы | Время | Кто |
|---|---|---|
| 0–1 (инфраструктура, роли) | ~30 мин | админ |
| 2–4 (контент → плейлист) | ~1 час | оператор + модератор |
| 5–6 (эфир, экран, бегущая строка) | ~1,5 часа + наблюдение | оператор у экрана |
| 7–8 (отчёты, биллинг) | ~40 мин (после 1–2 ч эфира) | админ/аудитор |
| 9 (сбои) | ~1 час, по согласованию | админ + человек у экрана |
| 10–11 (обновления, восстановление) | ~30 мин | админ |

Итого чистой работы ~5 часов, календарно — один рабочий день (эфиру нужно
время накопить показы). После прохождения всех P0/P1 систему можно считать
принятой в эксплуатацию; P2 — по мере возможности.
