# 10. План проверки работоспособности всех функций (развёрнутая система)

Полная функциональная приёмка на **боевом контуре**: сервер `10.0.119.100` +
пилотный мини-ПК. Порядок этапов важен — каждый следующий опирается на
предыдущий. В каждом пункте: *действие → ожидаемый результат*. Отмечайте
чек-боксы; если результат другой — фиксируйте и смотрите
[runbook](../Техдокументация/03_RUNBOOK_ИНЦИДЕНТЫ.md).

Приоритеты: **P0** — без этого система не работает; **P1** — важные функции;
**P2** — дополнительные/разовые проверки.

> ✅ — уже проверено на пилоте 27.07.2026 (при повторной приёмке можно
> перепроверить быстро).

  проверку» → **все пункты зелёные** (БД, миграции 26, Redis, Celery, MinIO,
  NTP, диски, свежесть бэкапа).
- [ ] **selfheal с хоста**: `bash selfheal.sh --dry-run` → «Все проверки
  пройдены», код возврата 0.
- [ ] **Smoke-тест** (неразрушающий, создаёт и удаляет своё):
  «пройдено 29, провалено 0». На боевом сервере пароль admin сменён — передайте

  ```bash
  read -rsp "Пароль admin: " ADMIN_PASS; echo; ADMIN_PASS="$ADMIN_PASS" bash smoke_test.sh; unset ADMIN_PASS
  ```
- [ ] **Бэкап вручную**: Настройки → «Создать бэкап сейчас» → файл появился в
  списке; авто-бэкап моложе 26 ч (это же видит самодиагностика).
- [ ] **NTP**: `docker exec ds_ntp chronyc tracking` → источник выбран; в

## Этап 1. Доступ и роли (P0, ~15 мин)

- [x] ✅ Вход `admin`; при первом входе со стандартным паролем — принудительная
  смена.
- [ ] Создать тестовых пользователей (Настройки → Пользователи, под
  `superadmin`): **аудитор** и **модератор**.
- [ ] Вход **аудитором**: видит дашборд/отчёты/журнал, **нет** кнопок
  создания/изменения; раздел «Обновление агентов» скрыт.
- [ ] Вход **модератором**: работает только «Модерация» (одобрить/отклонить);
  загрузка/расписание недоступны.
- [ ] **Блокировка**: заблокировать тестового пользователя → вход отклоняется;
  разблокировать → вход работает.
- [ ] Отчёт «Входы пользователей в панель» показывает эти входы.

## Этап 2. Медиатека (P0, ~30 мин)

- [ ] **Загрузка рекламного ролика** (реальный MP4 H.264 ≤1080p): категория
  например «Продукты», маркировка 0+ → статус «на модерации», в эфир не идёт.
- [ ] **Баннер** JPG/PNG с длительностью 15 с → принят, в карточке «15 с».
- [ ] **Служебный ролик** (категория «Служебный контент») → сразу `approved`.
- [ ] **Заглушки**: Медиатека → Заглушки → «Загрузить заглушки» (3–5 роликов
  суммарно ≥ 5 мин) → итог «N шт · время» совпадает.
- [ ] **Общая медиатека**: создать папку, загрузить файл в неё, переложить файл
  между папками селектом на карточке.
- [ ] **Запреты**: попытка загрузить с категорией «табак» → загрузка отклонена.
- [ ] **Битый файл** (например, переименованный .txt в .mp4) → отклонён
  проверкой, в медиатеку не попал.
- [ ] **Поиск** сверху находит ролик по названию/рекламодателю; миниатюры
  отображаются.
- [ ] Цена рекламодателя ₽/мин сохраняется (понадобится в этапе 8).

## Этап 3. Модерация (P0, ~10 мин)

- [ ] Под **модератором**: «▶ Просмотр» воспроизводит ролик.
- [ ] **Одобрить** ролик из этапа 2 → пропал из очереди, статус `approved`.
- [ ] Загрузить второй рекламный ролик и **отклонить с причиной** → в
  Медиатеке метка «отклонён», причина видна по наведению.
- [ ] Оба решения видны в **журнале операций** (кто/когда/что).

## Этап 4. Плейлисты и эфирный блок (P0, ~15 мин)

- [ ] Создать плейлист → по умолчанию бейдж **«блок 60 мин»**.
- [ ] Добавление ролика — **выбор «папка → ролик»**; добавить одобренный ролик.
- [ ] Панель блока: «Основные … Заглушками добавится … Итого ≤ 60 мин»;
  предупреждение о заглушках соответствует их наличию (до этапа 2.4 —
  «заглушек нет», после — «будут повторяться» или без предупреждений).
- [ ] **Дубль**: повторное добавление того же ролика → отказ с пояснением.
- [ ] Добавить этот же ролик во второй плейлист → предупреждение «уже
  используется в …».
- [ ] Переключить в **произвольный** режим и обратно; сменить целевую
  длительность (например 30 мин) → расчёт пересчитался.

## Этап 5. Расписание и эфир на экране (P0, ~30 мин + наблюдение)

- [ ] Назначить плейлист на **текущий час** пилотного экрана → мини-ПК начал
  играть в течение ~1 минуты.
- [x] ✅ На физическом экране: **mpv во весь экран**, без рамок/панелей/курсора.
- [ ] **Заглушки в эфире**: заставки идут **между** основными роликами
  равномерно, блок не превышает целевую длительность.
- [ ] **🔎 Симулятор** на этот час совпадает с тем, что реально играет.
- [ ] **Переопределение даты** (календарь месяца) на завтра → слот виден;
  «Сбросить переопределения месяца» возвращает шаблон.
- [ ] **⧉ Скопировать расписание экрана** (можно на тот же экран-группу) —
  слоты продублировались.
- [ ] **Уровни**: назначить слот на **группу** → экран играет его там, где нет
  своего слота; слот **экрана** перебивает групповой.
- [ ] **Эфир сети**: включить общий плейлист → экран переключился; «Снять
  общее» → вернулось расписание.
- [ ] **Массовое удаление**: галочками удалить выбранные слоты; «очистить
  день» кликом по дню.
- [ ] Ролик с истекающим сроком «по» → после срока пропадает из эфира
  (видно в симуляторе; плитка «Истекают ≤3 дней» на дашборде).

## Этап 6. Управление экраном (P0/P1, ~20 мин)

- [x] ✅ **■ Стоп** → показ остановился; **▶ Показ** → возобновился (без
  перезапуска агента).
- [x] ✅ **Бегущая строка**: запустить (текст/цвет/скорость) → плавная строка
  поверх видео; время показа 0 = бессрочно; «Снять» → исчезла.
- [ ] **Авто-снятие строки**: при активной строке нажать «Стоп» (или дождаться
  смены плейлиста по расписанию) → задание исчезло из раздела «Бегущая
  строка», в журнале — «снята автоматически».
- [ ] **↺ Агент** (перезапуск) → экран вернулся онлайн ≤1 мин, эфир
  продолжился.
- [ ] **Громкость день/ночь**: изменить → звук на экране изменился по времени
  суток.
- [ ] **Питание монитора** (P1, вечерний тест): задать окно ⏻ → монитор
  выключился/включился по расписанию.
- [ ] **Синхростарт** (P2 — когда появится второй экран): два экрана стартуют
  ролик синхронно.
- [ ] **Телеметрия экрана** на карточке актуальна: свободный диск, версии
  ОС/плеера, разница часов, «что играет» (heartbeat ~30 с).
- [ ] **📺 Контроль монитора** (V2, нужен агент ≥1.2.0): бейдж у экрана зелёный.
  Выдернуть кабель HDMI → в течение ~1 мин бейдж стал красным, под карточкой
  строка «⚠ Монитор отключён от видеовыхода», на Дашборде — блок «Монитор не
  подключён»; через 3 мин пришло уведомление в MAX. Вернуть кабель → бейдж
  зелёный, в MAX сообщение «монитор снова подключён».
  Если бейдж остался серым — драйвер не отдаёт статус, снимите с мини-ПК
  вывод `grep -H . /sys/class/drm/*/status` и приложите к отчёту приёмки.
- [ ] **🧾 Диагностика** (нужен агент ≥1.1.2): нажать кнопку → через ~30 с
  в списке под экраном появился архив → скачивается и открывается
  (внутри journalctl, лог агента, конфиг без токена, версии, диск, плеер,
  часы).

## Этап 7. Отчёты (P1, после 1–2 часов эфира)

- [ ] **Журнал показов** наполняется; количество показов ролика за час ≈
  ожиданию из симулятора.
- [ ] **Время показа по роликам/рекламодателям** ≈ длительность × показы.
- [ ] **Отчёт «Заглушки»**: показы заставок отражают реальный эфир.
- [ ] **Занятость инвентаря** отражает заполненность шаблона.
- [ ] Единая **панель фильтров** (дата/рекламодатель/ролик/экран) фильтрует все
  секции.
- [ ] **Фильтр таблицы** («🔍 Фильтр по этой таблице…») сужает строки; клик по
  заголовку столбца сортирует (повторный — в обратную сторону).
- [ ] **День недели**: селект в панели фильтров (и в Журнале показов) оставляет
  только показы выбранного дня; в журнале и выгрузках есть столбец «День».
- [ ] **Конструктор**: собрать отчёт, сохранить, открыть сохранённый.
- [ ] **⚖ Для ФАС** — выгрузка формируется (декларации + решения модерации +
  показы).
- [ ] **↓ Экспорт отчётов** — файл скачивается и открывается.

## Этап 8. Кампании и биллинг (P1, ~20 мин)

- [ ] **Скидка/доплата** с примечанием меняет итог; «Оплачен»/«Вернуть».

## Этап 9. Отказоустойчивость — управляемые сбои (P0, ~1 час)

> Делать в согласованное время; это главная ценность приёмки.

- [ ] **Обрыв сети мини-ПК** (вынуть кабель на 10 мин): экран продолжает
  играть скачанный контент **автономно**; на дашборде — офлайн; вернуть сеть →
  экран онлайн, в отчёте «Потери связи» появилась запись с длительностью.
- [ ] **Обесточивание мини-ПК** (выключить питанием, включить): автологин →
  агент стартовал сам → mpv во весь экран, эфир продолжился **без участия
  человека** (главный signage-тест).
- [ ] **Простой экрана** виден в отчёте «Простой»; при настроенном MAX —
  пришло уведомление об офлайне и о восстановлении.
- [ ] **Перезапуск сервера**: `docker compose restart` → панель вернулась,
  экраны переподключились; `bash selfheal.sh` после — всё зелёное.
- [x] ✅ **«Чёрная панель»** (nginx держит старый IP api): лечится
  `docker restart ds_nginx` / selfheal (runbook §1.5).
- [ ] **Диск**: убедиться, что предупреждение диагностики о занятости >85%
  осмысленно (можно не имитировать, достаточно текущих значений).

## Сводка трудозатрат

| Этапы | Время | Кто |
|---|---|---|
| 0–1 (инфраструктура, роли) | ~30 мин | админ |
| 2–4 (контент → плейлист) | ~1 час | оператор + модератор |
| 5–6 (эфир, экран) | ~1 час + наблюдение | оператор у экрана |
| 7–8 (отчёты, биллинг) | ~40 мин (после 1–2 ч эфира) | админ/аудитор |
| 9 (сбои) | ~1 час, по согласованию | админ + человек у экрана |
| 10–11 (обновления, восстановление) | ~30 мин | админ |

Итого чистой работы ~4–5 часов, календарно — один рабочий день (эфиру нужно
время накопить показы). После прохождения всех P0/P1 систему можно считать
принятой в эксплуатацию; P2 — по мере возможности.
