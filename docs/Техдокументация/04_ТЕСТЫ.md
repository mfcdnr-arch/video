# 04. Тесты

В проекте три уровня проверки перед релизом: **регрессионные unit-тесты**
(pytest: математика биллинга и кампаний, плейлисты и показы, бегущая строка, код агента),
**smoke-тест** (сквозной, против живого стека) и **UI/E2E-тест** (браузерный
прогон панели). Для работы без боевого сервера есть **локальный стенд
разработки** — `dev_stand.sh` (§0).

---

## 0. Локальный стенд разработки — `dev_stand.sh`

Обычный стек `docker-compose.yml` с надстройкой `docker-compose.dev.yml` под
отдельным именем проекта **`dsdev`** (свои тома — данные боевого стека и чужих
проектов не затрагиваются). **Только для разработки, на боевом сервере не
используется.**

```bash
bash dev_stand.sh up      # собрать и поднять стенд (+ миграции)
bash dev_stand.sh down    # остановить, данные сохраняются
bash dev_stand.sh reset   # остановить, СТЕРЕТЬ тома и поднять заново (чистая БД)
```

- Панель — **`http://127.0.0.1:8088`**, порт открыт **только на loopback**
  (у admin стенда известный пароль, из локальной сети стенд виден быть не
  должен). NTP наружу не публикуется.
- Вход — `admin`, пароль в файле **`.dev_admin_pass`** (создаёт `dev_stand.sh`,
  файл в `.gitignore`; значение — сид миграции 001, принудительная смена пароля
  на стенде снята). На сервере `install_server.sh` генерирует случайный пароль.
- Контейнеры называются так же, как на сервере (`ds_api`, `ds_postgres`, …),
  поэтому `smoke_test.sh` и `migrate.sh` работают со стендом без правок.
  Боевой стек и стенд на одной машине одновременно не поднять.
- После `reset` БД пустая — ни экранов, ни роликов; тесты, которым это нужно,
  заводят свои данные сами и убирают их (см. §3).
- Миграции на `reset` применяет initdb, а `migrate.sh` только начинает учёт
  (baseline): ждите «Учёт миграций начат: … — 34 шт.» и «применено 0, уже было
  34». В `sync_groups` — по одной строке «Зал 1» и «Все экраны»:

  ```bash
  docker exec ds_postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT name, count(*) FROM sync_groups GROUP BY name"'
  ```

Пароль в команды подставляйте так, чтобы он не попадал в историю и вывод:

```bash
SMOKE_ALLOW_BROADCAST=1 ADMIN_PASS=$(cat .dev_admin_pass) bash smoke_test.sh
E2E_ALLOW_BROADCAST=1 ADMIN_PASS=$(cat .dev_admin_pass) DS_URL=http://nginx bash ui_test.sh
```

`SMOKE_ALLOW_BROADCAST=1` включает в smoke шаг «Общий эфир» (§2), а
`E2E_ALLOW_BROADCAST=1` — такой же шаг в браузерном прогоне (§3) и ещё бегущую
строку «на все экраны» (шаг 10 из §3): они идут на **все** экраны сети, поэтому
**только на стенде** — на боевом сервере переменные не задавайте (шаги сами пишут
«пропущено» и ничего не трогают). Прежнее состояние общего эфира тест запоминает и
возвращает в конце, даже если проверка упала; строка «на все экраны» снимается тут
же.

## 1. Регрессионные тесты (pytest) — `server/tests/`

### Что это и зачем
Автотесты, которые защищают **«денежную» и учётную математику** от случайных
поломок при будущих правках:
- **биллинг** — расчёт суммы счёта по тарифу (за показы / за минуты), округление
  до копеек, разбор дат периода, преобразование объёмов из `play_log`, итог с
  учётом скидки/доплаты;
- **кампании** — план/факт (план = цель × прошедшие дни), процент выполнения,
  недобор, переходы статусов (scheduled/active/finished/paused), границы дат по
  МСК, дневная детализация;
- **контроль монитора** — разбор `/sys/class/drm/*/status` агентом (в том числе
  «статус неизвестен» и виртуальные выходы, которые нельзя принимать за
  отключённый монитор) и правило тревоги на сервере;
- **карточка рекламодателя** — границы московских суток в UTC: ошибка на три
  часа тихо перенесла бы показы соседних суток в чужой период, а значит и в
  чужой счёт и эфирную справку;
- **плейлисты** — развёртка повторов ×N, мягкие предупреждения («подряд»,
  «доля», «дубли»), «общий час» для режима «по очереди»; создание и замена
  роликов плейлиста одним запросом (всё или ничего);
- **показы по датам** — даты и целые часы, статусы (запланирован / идёт /
  закончился / остановлен), поиск пересечений, решения «заменить» / «по
  очереди» / «оставить „…“» (yield: уступить показу или переопределению,
  цепочки уступок только к старшим, устаревшие решения о более новых показах
  не действуют), выбор плейлистов на экран в текущий час, расписание недели,
  подстановка решений при правке (свои или перевёрнутые решения показов,
  сохранённых позже), разбор строк БД, тело и ответы API;
- **дубли в медиатеке** — группировка роликов по md5, ответ 409 и главное:
  отклонённая загрузка не оставляет ни файла на диске, ни записи в БД;
- **группы экранов** — `POST /groups`: занятое имя → 409 (и при гонке, когда
  дубль ловит уникальный индекс миграции 033), пустое → 400, JSON панели и
  query-параметры; регистрация экрана берёт «Все экраны» с `ORDER BY id`; сиды
  групп в 001/002 — `WHERE NOT EXISTS`, а не `ON CONFLICT` без ключа;
- **«в сети»** — единое правило (`screen_online.py`): последний сигнал экрана не
  старше 5 минут, шаблоны SQL с псевдонимом таблицы, поле `online` /
  `offline_for_seconds` в списках экранов и дашборда, `group_id` в `GET /minipc`;
  отчёты, самодиагностика и WS-пуш дашборда берут то же правило (своих «5 минут»
  и `screens.status` в них нет);
- **общий эфир** (`broadcast_rules.py`, `broadcast_store.py`, `routers/broadcast.py`) —
  срок «до отмены» / «до ЧЧ:00» (час 1–24, позже текущего, мусор → 400), «идёт ли
  эфир сейчас» (срок вышел — эфир выключен ровно в срок), включение / смена /
  выключение и запись в журнал («включён», «сменён», «выключен», «завершён по
  времени»), истечение по времени (`expire_due`) и то же при включении /
  выключении в первую минуту после срока (до тика Celery: сначала «завершён по
  времени», второго «выключен» нет), дата окна `on_date` (устаревшая → 400 с
  текстом окна, мусор → 400, нет → прежнее поведение), id плейлиста (`²`,
  не-ASCII цифры, больше int4, строка в тысячи цифр → 400, а не 500), читатели эфира — лента экрана
  (эфир, которому на экране нечего играть, не перекрывает расписание), список
  закачки, симулятор, дашборд;
- **«Эфир сети»** (`network_live.py`, `routers/network.py`) — что идёт на экране
  сейчас, до какого часа и что дальше / после эфира при каждом источнике (шаблон,
  показ, «по очереди», замена на дату, «выключено», эфир, нет расписания; на
  экране, где эфиру нечего играть, «дальше» — ближайшая смена его расписания;
  показ, замену и слот шаблона, которым нечего играть, страница пропускает так
  же, как лента экрана — пустой слот шаблона уступает слоту «весь день»),
  сборка ответа `GET /network/live` (счётчики, тип площадки `venue_type`,
  «играет ролик», один пакетный запрос на всех, а не по запросу на экран),
  доступ роли «рекламодатель» к этим путям закрыт;
- **симулятор** (`routers/schedule.py`, шаг «недельный шаблон») — слот выбирается так
  же, как в ленте экрана, у агента и на странице «Эфир сети» (`placements_logic.template_tops`):
  вершина часа (экран > группа > сеть) берётся до фильтра роликов, пустая уступает слоту
  «весь день», а не слоту уровнем ниже на тот же час; пуст и «весь день» — заглушки;
- **бегущая строка** (`ticker_rules.py`, `ticker_store.py`, `routers/ticker.py`, Celery
  `expire_tickers`, агент 1.4.0) — срок («до снятия», «до ЧЧ:00» с защитой `on_date`,
  «на N минут» от 1 до 1440, через полночь), текст 1–200 знаков и мусор в теле →
  400 по-русски, прежнее тело запроса (`is_all`, `duration`), «где» на момент показа
  (все / группы / экраны, неизвестные id отброшены), строки экрана в порядке запуска,
  причины «бежит на X из N» в порядке проверки (не в сети → старый агент → «Стоп» →
  питание → бежит → ждём подтверждения 90 с → не подтвердил) и подсчёт итога; SQL
  хранилища на подменной сессии: все моменты — наивное МСК из Python, а не `NOW()`;
  правка без срока оставляет прежний, истёкшую строку править нельзя, снятие одной
  строки не гасит остальные, `commit` хранилище не делает; текст: `\t \v \f`, NEL,
  U+2028 / U+2029 → один пробел (в коде — escape-ы), NUL, прочие управляющие символы и
  одинокие суррогаты → 400 по-русски; правка (PUT) без `target` → 400 «Укажите, где
  показывать строку» (POST без него — по-прежнему «все»); `problems[]` несёт
  `screen_id` (экраны с одним именем различимы); команды старым агентам — состояние:
  перед новой `ticker_show` / `ticker_hide` экрана ожидающие `ticker_*` гасятся (в очереди
  одна, прочие команды и чужие экраны не тронуты), это же в ветке «Стоп»; heartbeat будит
  подключённый по WS экран с командой старше 10 с (нет WS — нет ни запроса, ни сигнала;
  сбой проверки heartbeat не роняет); API: обзор считает «бежит»
  по отчёту экранов, изменение и снятие доходят и до экранов «до», и до экранов
  «после», один `commit` раньше WS-будильника, «Стоп» не снимает строки (старому агенту
  `ticker_hide` только при живых строках), «Показ» возвращает, сбой строк не
  роняет ни heartbeat, ни ленту, ни «Стоп»/«Показ» (ключ `tickers` в ленте
  пропадает), Celery снимает по сроку одним `commit` и пишет «снята по сроку»;
  агент — очередь строк (по проходу каждой), срок по часам агента, пауза на «Стоп» и
  при выключенном мониторе, ключ `tickers` без значения «ничего не менять», остаток
  пачки команд за одно пробуждение, `ticker_state` в heartbeat;
- **файлы медиатеки только по входу** (`media_access.py`, `routers/media.py`,
  `routers/auth.py`) — ролик, миниатюра и проверка nginx для `/media/<имя>`: без входа,
  с мусором, чужим ключом, истёкшим входом и несуществующим пользователем — 401 на
  любой номер; панель (супер-админ, админ, аудитор, модератор) — любой файл, в том
  числе на модерации и скан договора; рекламодатель и заблокированный — 403; экран по
  `X-Token` (и `Bearer` с токеном экрана) — только готовый одобренный ролик, прочее
  404, миниатюры и `/files/auth` — 401; cookie `ds_media` (`POST /session/media`):
  httpOnly, `SameSite=Strict`, без `Secure` по HTTP, живёт не дольше входа, открывает
  файлы без заголовка, снимается `DELETE`; истёкшая, чужая (токен входа в cookie,
  чужой `scope`, мусор) — 401, cookie как токен входа — 401, пользователь проверяется
  на каждый запрос; за nginx — `X-Accel-Redirect` (имя в `%`-кодировке, `filename*`),
  Range за концом файла — файл целиком, отказ — без `X-Accel-Redirect`;
- **«ролик можно играть»** (`playable_store.py`) — одно правило (готов, одобрен, алкоголь только на
  площадке с алколицензией, срок показа не вышел) у ленты экрана, часового блока, обзора сети и
  флагов `GET /playlists`: тест проверяет сам фрагмент и что копий фильтра в роутерах не осталось;
  слоты недельного шаблона в ленте экрана берут тот же фрагмент — со сроком показа;
- **агент** (`agent/tests/`) — повторы ×N в списке для плеера, срок действия
  `active_until`, повторный запрос ленты на стыке часов, выбор файлов
  текущего плейлиста, защита очистки диска от сбоя запроса списка файлов (§1.1).

Раньше это проверялось только вручную при каждой доработке. Теперь одна команда
подтверждает, что формулы не «поехали».

### Как устроено
Тесты **не требуют реального Postgres**: сессия БД подменяется лёгким моком
(`FakeDB` в [`conftest.py`](../../server/tests/conftest.py)), который возвращает
заранее заданные строки. Проверяется именно **чистая математика** над этими
данными. Корректность самих SQL-запросов проверяет smoke-тест против живого
стека (см. §2) — это разные уровни, они дополняют друг друга.

### Как запускать
Одной командой из каталога проекта:

```bash
bash run_tests.sh
```

Скрипт [`run_tests.sh`](../../run_tests.sh) сам ставит dev-зависимости (`pytest`)
в работающий контейнер `ds_api` и прогоняет `server/tests`. Запускать можно
**после любого обновления/пересборки** — воспроизводимо.

`pytest` **не входит** в production-образ (он не нужен для работы системы) —
dev-зависимости вынесены в
[`server/requirements-dev.txt`](../../server/requirements-dev.txt). Эквивалент
вручную:

```bash
docker exec ds_api pip install -r /app/requirements-dev.txt
docker exec -w /app ds_api python -m pytest tests -q
```

Ожидаемый результат — все тесты зелёные, например:
```

```

> В `docker-compose.yml` каталог `agent/` смонтирован в `ds_api` как `/agent`
> (только для тестов) — поэтому тесты разбора сигнала монитора, которым нужен
> код агента, выполняются. Если запускать pytest в образе без `/agent`, они
> пропускаются (`973 passed, 1 skipped`) — это не ошибка.

> Установка `pytest` в контейнер **эфемерна** — теряется при пересборке образа
> (`docker compose up --build`). Это норма: перед прогоном просто повторите шаг 1.

> Настройки pytest — в `server/pytest.ini` (там же глушатся посторонние
> предупреждения: passlib про устаревший модуль `crypt` в Python 3.11+ и starlette
> про устаревший алиас anyio при импорте `TestClient` — к нашему коду они отношения
> не имеют).

### 1.2. Миграция 033 (слияние дублей групп) — на живом Postgres
pytest без БД проверяет только текст миграции, поэтому само слияние проверено
на одноразовом контейнере `postgres:15-alpine` (не на стенде): 001–032 в старом
виде дважды (так появлялись дубли), третья копия «Все экраны», на копиях —
экраны, групповые слоты, замены на дату и кампании, в том числе совпадающие.
Ожидаемое после 033: по одной группе на имя с минимальным id; все ссылки
переехали на неё; при совпадении слота (день + час) или замены (дата) осталась
строка оставшейся группы, а среди двух копий — копии с меньшим id; слоты сети и
экранов, замены экранов не тронуты; повторный запуск 033 и всех 001–033 ничего
не меняет; новая «Зал 1» отклоняется индексом `uq_sync_groups_name`.

Путь обновления боевого повторён в отдельном compose-проекте: установка из
старых файлов (`migrate.sh` дал «применено 32» и дубли) → новые файлы →
`migrate.sh`: «применено 1, уже было 32», дубли слиты, экран со «второй»
«Все экраны» переехал на первую.

### 1.3. Миграция 034 и SQL бегущей строки — на живом Postgres
pytest гоняет SQL хранилища на подменной сессии и проверяет только текст
миграции 034, поэтому настоящий SQL и перенос старых строк проверяются на стенде:
`dev_stand.sh reset` → в журнале «Учёт миграций начат: … — 34 шт.», в
`ticker_templates` три стартовых шаблона; шаг «Бегущая строка» в `smoke_test.sh`
(§2) гоняет запросы на живой базе. Перенос старых строк (при разработке, на БД
стенда): прежние строки разных видов (активная без срока, со сроком, неактивная,
истёкшая) и строка, созданная новым кодом, → после 034 неактивная и истёкшая
удалены, активная без срока — `target = all`, срок пуст («до снятия»), время
запуска переведено из UTC в МСК, со сроком — срок тоже в МСК, строка нового кода не
тронута; повторный запуск файла (вручную: `docker exec -i ds_postgres psql -U
display_user -d display_system < server/migrations/034_ticker_redesign.sql`) даёт тот
же результат и не дублирует шаблоны. Эту проверку стоит повторить на копии боевой
базы перед выкаткой на сервер, где есть строки.

## 2. Smoke-тест — `smoke_test.sh`

Сквозной прогон **против живого стека**: проверяет, что все 7 контейнеров живы,
работает вход, здоровье API и полный цикл «экран → медиа → плейлист →
расписание», а также доступность модулей (дашборд, отчёты, биллинг, кампании,
модерация, уведомления). Сюда же входят новые плейлисты и показы: проверка
повторов `/playlists/check`, создание плейлиста одним запросом, замена роликов,
**дубли** (повторная загрузка → 409 со сведениями о ролике, `allow_duplicate`,
список дублей, на диске не остаётся лишнего) и **показы** (предпросмотр, создание,
список, правка, неделя, остановка и отмена на новом экране) и **что экран играет
и качает**: показ на текущий час на тестовом экране → лента
`/schedule/minipc/{id}` по `X-Token` экрана отдаёт `active_source = placement` и
`active_until` = следующий целый час, ролик показа появился в `/files/list/{id}`;
после «Остановить» показа нет ни в ленте, ни в списке закачки. На том же часе —
**одно пересечение**: второй показ без решения → 409, с «Заменить» — в ленте
он; предпросмотр правки (`exclude_id`) отдаёт сохранённое решение второго, а
для первого (старшего) — перевёрнутое решение второго («оставить»); после
правки на «Оставить „…“ на это время» (yield) лента снова отдаёт первый показ,
а в списке показов — строка «уступает». **Обзор сети** (`GET /network/live`, страница
«Эфир сети»): тестовый экран есть в таблице, счётчики сходятся, «сейчас» — показ
на текущий час до следующего целого часа (экран ещё не выходил на связь — не в сети,
«играет ролик» пуст); после heartbeat с `playing_file` — в сети, ролик сопоставлен
с медиатекой (id и название); `GET /network/playlist/{id}/usage` считает слоты
шаблона (≥ 1), несуществующий плейлист → 404. Все тестовые данные создаются с
префиксом `SMOKE_` и удаляются в конце.

**Скачивание только по входу** (шаг «Бэкапы и диагностика: скачивание только по входу»):
бэкап — полный дамп БД, номера идут подряд, поэтому без входа `GET /backups/{id}/download`
и `GET /diagnostics/{id}/download` обязаны отвечать 401 на любой номер, и токен экрана
(`X-Token`) их тоже не открывает. По входу: если на сервере есть бэкап, последний
скачивается (200); если нет (чистый стенд) — 404 на несуществующий номер. Архивов
диагностики у SMOKE-экрана нет — по входу 404. Шаг ничего не создаёт и идёт и на боевом.

**Файлы медиатеки только по входу** (шаг «Файлы медиатеки: только по входу») идёт
**через nginx** (`http://nginx` изнутри `ds_api`): Range, `/media/` и `X-Accel-Redirect`
живут там. Без входа ролик (`/api/files/download/{id}`, в том числе несуществующий
номер), миниатюра и `/media/<имя>` (GET и HEAD) — 401; поддельный токен и токен входа
вместо cookie — 401; токен экрана не открывает миниатюру и `/media/` (401). Экран по
`X-Token`: одобренный SMOKE-ролик скачивается целиком (размер совпадает с медиатекой),
**докачка** — `Range: bytes=100-` → 206 и остаток файла; ролик на модерации — 404.
По входу (`Bearer`): ролик, ролик на модерации, миниатюра, `HEAD /media/<имя>` — 200.
Cookie: `POST /api/session/media` → `/media/<имя>` с `Range: bytes=0-99` — 206 и 100
байт, миниатюра и «Скачать» — 200; после `DELETE /api/session/media` — 401. Шаг
работает с роликами основного цикла, сам ничего не создаёт и идёт и на боевом.

**Бегущая строка** (шаг «Бегущая строка: запуск, правка, снятие (только тестовый экран)»)
создаёт строки и шаблоны **только на тестовом экране `SMOKE_…`** (цель «Экраны»): smoke
идёт и на боевом сервере, а строка «на все экраны» засветила бы тест у посетителей.
Экран подаёт сигнал как агент 1.4.0 (`ticker_state` в heartbeat). Проверяется: запуск «на
15 минут» (срок по МСК, осталось ~900 с); обзор `GET /tickers/overview` («на 1 экране»,
по отчёту экрана строка бежит, у экрана одна живая строка, группы и шаблоны на месте);
`GET /tickers` по-прежнему список; старому агенту поставлена `ticker_show`; лента экрана
отдаёт строку с видом и сроком; **«Стоп» строку не снимает** (она остаётся в обзоре и в
ленте, экрану поставлены `stop` и `ticker_hide`, причина «остановлен»), «Показ» возвращает
`ticker_show`; на экране без живых строк «Стоп» и «Показ» ставят только `stop` / `resume`;
правка без срока оставляет срок прежним; записи журнала «запущена / изменена / снята»;
повторное снятие и правка снятой — 404; прежнее тело запроса (`is_all`, `duration` = 60 с);
пустой текст, NUL в тексте, срок «0 минут» и несуществующий экран — 400 по-русски, не 500;
две правки подряд оставляют в очереди экрана одну `ticker_show` (устаревшая погашена);
правка без «где» — 400 «Укажите, где показывать строку»; у проблемного экрана в обзоре
есть `screen_id`; шаблон:
создать, найти, переписать, удалить, повторное удаление — 404. Строки и шаблоны с
префиксом `SMOKE_` убираются в «Уборке» и при обрыве проверки на полпути.

**Общий эфир** (шаг «Общий эфир: срок «до ЧЧ:00»») идёт на **все экраны** сети, поэтому
выполняется только при `SMOKE_ALLOW_BROADCAST=1` (стенд); без переменной печатается
«эфир на все экраны — пропущено» и ничего не включается. Шаг запоминает, что шло
в эфире, включает свой плейлист `SMOKE_bc_…` до следующего целого часа (час и ожидаемый
срок считаются в `ds_api` по МСК, при 23 час окончания = 24), проверяет `GET /broadcast`
(`is_on`, `until_at`), запись в журнале и срок на дашборде (`broadcast_until`). Глазами
тестового экрана (X-Token): пока плейлист эфира пуст, экрану нечего играть — лента
не отдаёт эфир (экран не гаснет); с роликом — лента отдаёт `active_source = broadcast`
и `active_until` = срок эфира, ролик эфира есть в `/files/list/{id}`, симулятор пишет
«общий эфир «…» до ЧЧ:00». Затем: час окончания, не позже текущего, и 25 → 400;
неизвестный плейлист → 404; старый вызов без тела (`?playlist_id=N`) = «до отмены»
(«Общий эфир сменён», `active_until` = null); выключение — лента не отдаёт эфир, ролика
эфира нет в списке закачки. В обзоре сети (`/network/live`) то же видно глазами админа:
пока плейлист эфира пуст — у экрана `broadcast_skipped` и растёт `unplayable_screens`,
а «дальше» у него — ближайшая смена его расписания (как без эфира);
с роликом — «сейчас» `broadcast` до срока, «после эфира» заполнено, `next` пуст;
после выключения эфира в таблице нет. В конце прежнее
состояние эфира возвращается (даже если проверка упала или скрипт прервали), плейлист
проверки удаляется. Само истечение по времени (Celery `expire_broadcast` раз в минуту)
smoke не ждёт — оно покрыто pytest (`test_broadcast.py`), а на стенде проверяется
вручную: сдвинуть `until_at` в прошлое в таблице `network_broadcast` и через минуту
увидеть в журнале «Общий эфир завершён по времени».

```bash
cd Video_miniPC_v16.2_modular
bash smoke_test.sh                           # боевой сервер и стенд: без шага «Общий эфир»
SMOKE_ALLOW_BROADCAST=1 bash smoke_test.sh   # только стенд: с шагом «Общий эфир»
```

Код возврата `0` — можно выпускать; иначе число упавших проверок. Ожидаемый
итог — `пройдено 191, провалено 0`, а со `SMOKE_ALLOW_BROADCAST=1` (стенд) —
`пройдено 219, провалено 0` (число проверок растёт вместе с тестом).
Остальные ветки с пересечениями и решениями («по очереди», переопределения,
цепочки уступок) smoke не проходит — они покрыты pytest и E2E (§3).

## 3. UI/E2E-тест панели — `ui_test.sh`

### Зачем отдельный уровень
Главный вывод пилотного развёртывания: **почти все дефекты панели нашлись
только живым кликом**. Кнопка звала неверный HTTP-метод (405 при создании
экрана), падала в JS или молча ничего не делала — а `smoke_test.sh` при этом
был зелёный, потому что проверяет эндпоинты, а не интерфейс.

### Что проверяет
1. Вход в панель под администратором.
2. Открытие **всех 14 разделов** левого меню (заголовок сменился, вью не
   отдало «Ошибка: …»).
3. Нажатие **всех «безопасных» кнопок** каждого раздела — открыть форму,
   вкладку, фильтр, отчёт, модалку. Список действий **белый и перечислен
   поимённо** в `ui_tests/ui_test.js` (`SAFE_ACTIONS`): удаление, отправка
   форм, OTA, команды экрану и выгрузки файлов слепой прогон не нажимает никогда
   (кнопки «Скачать» бэкапа и архива диагностики проходит только шаг 14, «⤓ Скачать»
   ролика — шаг 15); кнопки
   общего эфира (`bc-open`, `bc-change`, `bc-off`, `bc-submit`) слепой прогон тоже
   не трогает — их проходит отдельный шаг 9. В списке «Эфира сети» — только
   безопасные `nl-open-playlist` (плашка плейлиста открывает панель) и
   `nl-close-drawer`. В «Бегущей строке» — только `ticker-details`, `ticker-pick-color`,
   `ticker-speed`, `ticker-term`, `ticker-target` (они ничего не отправляют); запуск,
   правку, снятие и шаблоны (`ticker-start`, `ticker-save`, `ticker-stop`,
   `ticker-save-template`, `ticker-update-template`, `ticker-template-delete`) проходит
   только шаг 10 — на своём тестовом экране. **Добавили новую кнопку — допишите её в список**, иначе она
   в прогон не попадёт.
4. Цикл **экрана** с уборкой за собой: создать → токен и ID показаны →
   копирование токена → виден в списке → удалить.
5. **Просмотр ролика**: клик по миниатюре в Медиатеке открывает окно с `<video>`
   или `<img>`, **кадр загрузился** (файл отдан по cookie входа: `<img>` с
   `naturalWidth > 0` или `<video>` с метаданными), Esc закрывает.
6. **Дубль при загрузке**: тот же файл через форму → окно «Такой ролик уже есть
   в медиатеке» (название существующего, три кнопки) → «Отмена» → копии в
   медиатеке нет. 409 сервера здесь ожидаем и провалом не считается.
7. **Плейлист целиком**, как это делает человек: «+ Плейлист» → название →
   поиск по части названия → галочка → «+» ×4 (повторы ×5, появилось
   предупреждение «подряд», кнопка «Создать всё равно») → «Создать и
   отправить →» → «Куда и когда»: «Выбрать экраны» → только свой тестовый
   экран `E2E_стенд_…`, завтра (МСК), 10–11 ч → пересечения (если есть —
   «Заменить», «ко всем» при двух и больше) → «Отправить на экраны» → в
   карточке плейлиста строка «запланирован» (тестовый экран, 10:00 – 11:00);
   «✎ Изменить ролики» и «📤 Отправить на экраны» открывают окна и закрываются
   по Esc → Расписание → «Экран» → **«По датам»**: сетка, листание ‹ ›, клетка показа завтра в 10:00 → карточка
   показа («запланирован»), «Сегодня» → в карточке плейлиста **«Отменить»** →
   плейлист удалён.
8. **Правило «в сети» и страница «Эфир сети»**. Тестовый экран `E2E_стенд_…`
   сигналов ещё не слал: в «Экранах» и на Дашборде у него «ни разу не выходил на
   связь»; после сигнала (`POST /heartbeat/{id}` с `X-Token`, как у агента) — в
   сети. Затем прогон создаёт свой плейлист `E2E_эфир_…` и показ на текущий час
   только на этот экран и проверяет страницу: шапка («N экранов · M в сети ·
   K не в сети · обновлено ЧЧ:ММ:СС»), колонки «Экран · Сейчас идёт · Играет
   ролик · Дальше», в строке экрана точка «в сети», плашка плейлиста,
   «📅 показ», название ролика, который сообщил экран; поиск по названию экрана
   («найдено 1»), по названию плейлиста (без учёта регистра) и пустой поиск
   («Ничего не найдено по запросу…»); клик по плашке → панель «О плейлисте»
   (сводка «1 ролик · 1 показ · …», «Сейчас идёт на 1 экране», «Где и когда
   идёт»: свой экран, часы, «идёт сейчас»), просмотр ролика из панели (Esc
   закрывает просмотр, панель остаётся), «✎ Изменить плейлист» (окно правки с
   подсказкой «идёт на 1 экране — изменения дойдут до него в течение минуты»,
   Esc без сохранения, страница и панель на месте), «📤 Отправить на экраны»
   (окно «Куда и когда», Esc), закрытие панели ✕ и Esc (фокус возвращается на
   плашку). **Зависший запрос**: прогон перехватывает `GET /network/live` и не
   отвечает — через 20 с страница обрывает его и пишет «Не удалось обновить
   данные: сервер не ответил за 20 с» над прежней таблицей, а после снятия
   перехвата («Повторить» или очередной тик) ошибка уходит. Полоса общего эфира: «Общий эфир выключен» и окно «Включить общий
   эфир на все экраны» — плейлист не выбран → «Включить» недоступна, по
   умолчанию «до» следующего часа (список часов до 24:00), жёлтое
   предупреждение, кнопка «Включить на 1 экране»; **«Отмена» ничего не
   включает** (проверяется по `GET /broadcast`). Автообновление раз в 30 с,
   красная строка при потере связи (режим «Офлайн»), предупреждение «нечего играть»
   в окне включения и подпись «не в сети X мин» E2E не проверяет (нужно
   ждать, ронять связь или сдвигать время сигнала) — это ручные пункты плана
   приёмки: [10_ПЛАН_ПРИЁМКИ_ФУНКЦИЙ](../Инструкции/10_ПЛАН_ПРИЁМКИ_ФУНКЦИЙ.md),
   этап 5, пять пунктов «Эфир сети: …»; шаблоны SQL правила «в сети» покрыты
   pytest (`test_screen_online`).
9. **Общий эфир** — шаг идёт на **все экраны сети**, поэтому выполняется только
   при `E2E_ALLOW_BROADCAST=1` (стенд); без переменной печатается «включение
   общего эфира на все экраны — пропущено» и ничего не включается. С переменной:
   прежнее состояние эфира читается ДО любых изменений и только из настоящего
   ответа — если `GET /broadcast` вернул не 200, шаг прерывается с понятной
   ошибкой, ничего не выключив и не «вернув» (иначе живой эфир «вернулся» бы
   выключенным); эфир уже шёл → выключается на время прогона; в конце часа (после 59:30)
   прогон ждёт следующий; «Включить на … экранах» «до» следующего часа → окно
   закрылось, **жёлтая полоса** («Общий эфир: «E2E_эфир_…» на всех N экранах»,
   «до ЧЧ:00 (осталось …)», «включил admin», «расписание на это время
   перекрыто»), в таблице у экрана «📡 общий эфир до ЧЧ:00» и последняя колонка
   «После эфира», в журнале «Общий эфир включён … до ЧЧ:00» → «Сменить
   плейлист» (окно с текущим плейлистом, Esc) → «Выключить» (с подтверждением) →
   серая полоса, колонка снова «Дальше», в журнале «Общий эфир выключен». В
   конце прежнее состояние эфира возвращается — **и когда проверка упала** (тот
   же плейлист и срок, если эфир шёл до прогона). Нюансы возврата: он идёт через
   `POST /broadcast/on`, поэтому в журнале появляется **новая** запись «Общий
   эфир включён» (с новыми «включил» и временем включения, а не прежними); если
   прогон не смог вернуть эфир (исключение или ответ не 200), он остаётся «не
   возвращённым» и итоговая страховочная уборка пробует ещё раз; если у прежнего
   эфира был срок «до ЧЧ:00» и он вышел, пока шёл прогон, то эфир уже закончился
   сам, и правильное прежнее состояние — «выключен» (прогон так и считает, это не
   ошибка).
10. **Бегущая строка** — только на **собственный тестовый экран** `E2E_стенд_…` (цель
   «Экраны»). Метка `E2E_строка_<STAMP>` в тексте строк и шаблонов нужна для уборки.
   Прогон шлёт сигнал тестового экрана «как агент 1.4.0» (`POST /heartbeat/{id}` с
   `agent_version` и `ticker_state`) — без этого панель считала бы агент старым. Путь
   человека: страница («Сейчас идут», «Новая строка», счётчик «0 / 200», «Запустить»
   неактивна) → текст (превью повторяет текст, счётчик; 201 знак → «201 / 200», запуск
   неактивен) → цвет, скорость, «На N минут» 15 → **«+ сохранить как шаблон»** (шаблон
   создан с этим видом и сроком, чип появился) → заново открыть страницу, клик по чипу
   (форма заполнена, появилась «Обновить шаблон») → «Экраны» (пока экран не выбран,
   «Запустить» неактивна) → свой экран, «30 мин» (проверка: список экранов в «Где» при
   перерисовке остаётся прокрученным — его искусственно сужают, прокручивают и меняют
   выбор, `scrollTop` не сбрасывается) → «▶ Запустить на 1 экране» → карточка:
   «1 экран: E2E_стенд_… · ещё N мин · запустил admin», «бежит на 0 из 1 — ждём
   подтверждения» (в обзоре у этого экрана есть `screen_id`), конструктор очистился, запись
   журнала «Бегущая строка запущена»; на
   сервере цель «экраны» только со своим экраном, ~30 минут. Сигнал экрана со строкой →
   страница сама (автообновление, до 15 с) пишет **«бежит на 1 из 1»**; «бежит на 1 из 1 ▾»
   раскрывает «Все экраны подтвердили» и сворачивает обратно. **«Стоп»** тестовому
   экрану (`POST /command/stop/{id}`) строку не снимает: она осталась, у карточки «бежит
   на 0 из 1 — остановлен («Стоп»)»; «Показ» — «бежит на 1 из 1». **«✎ Изменить»**: режим
   правки («Правка строки», «Сохранить изменения», срок «Не менять»), новый текст и цвет,
   срок прежний (`until_at` не сдвинулся), изменил admin, запись журнала «Бегущая строка
   изменена», конструктор вернулся к «Новая строка». **«Снять»** (с подтверждением):
   карточка ушла, строки нет на сервере, запись журнала «Бегущая строка снята». Шаблон:
   **«Обновить шаблон»** (дописан текст → шаблон переписан, чип с новым текстом), «×»
   (с подтверждением) → чип и шаблон ушли. Шаг «на все экраны» — **только при
   `E2E_ALLOW_BROADCAST=1`**: кнопка «▶ Запустить на N экранах» (N — число экранов
   стенда), карточка «на всех N экранах» («на единственном экране», если экран один),
   у тестового экрана `live_count = 1`, снять. Без переменной печатается «бегущая строка
   «на все экраны» — пропущено». Строки и шаблоны с меткой убираются в `finally`
   (до удаления экрана), в том числе когда проверка упала на полпути. Не проверяется
   E2E: автоснятие по сроку (Celery раз в минуту — покрыто pytest, E2E его не ждёт),
   смена часа при отправке «до ЧЧ:00», шаблон с прошедшим часом, права «только
   просмотр» — это ручные пункты плана приёмки
   ([10](../Инструкции/10_ПЛАН_ПРИЁМКИ_ФУНКЦИЙ.md), этап 6).
11. **Карточка рекламодателя**: открывается и все четыре вкладки (обзор,
   эфир, качество доставки, ролики) рисуются без ошибок.
12. **Изоляция роли «рекламодатель»** — самая дорогая ошибка раздела. Тест
   заводит настоящую учётку с ролью `advertiser`, входит ею в отдельном
   окне браузера и проверяет: в меню только его кабинет; `/advertisers`,
   `/minipc`, `/billing/invoices`, `/users` и чужая карточка отдают 403;
   свой кабинет открывается. Учётка и её кабинет удаляются в конце.
13. Индикатор монитора (бейдж 📺) отрисован на карточках экранов.
14. **Бэкап и архив диагностики — только по входу.** «Создать бэкап сейчас» →
   строка нового бэкапа в списке; прямой запрос без входа и по `X-Token` экрана — 401;
   кнопка «Скачать» шлёт запрос с `Authorization` и сохраняет на диск настоящий gzip
   под именем из списка; тестовый бэкап удаляется. Затем тестовый экран `E2E_стенд_…`
   присылает архив диагностики как агент (`X-Token`), под карточкой экрана появляется
   кнопка «Скачать» — те же проверки: без входа и по `X-Token` — 401, кнопка качает с
   токеном. Файл архива (20 байт) остаётся в томе `backup_data` стенда: удаление
   экрана стирает записи об архивах, но не файлы.
15. **Файлы медиатеки — только по входу** (на тестовом ролике `E2E_ролик_…`). Из
   страницы без cookie (`credentials: 'omit'`): ролик, миниатюра и `/media/<имя>` —
   401; токен экрана миниатюру не открывает (401), а одобренный ролик по `X-Token`
   скачивается (200). С cookie панели: `/media/<имя>` с `Range: bytes=0-9` — 206 и 10
   байт; миниатюра ролика в Общей медиатеке загрузилась; кнопка **«⤓ Скачать»**
   сохраняет на диск настоящий PNG под именем файла из медиатеки (ссылкой по cookie,
   не blob). `DELETE /api/session/media` (как при выходе) → `/media/<имя>` — 401;
   `mediaSession()` снова выдаёт cookie → 200. Ожидаемые 401 провалом не считаются.

**Тестовые объекты.** Для плейлиста нужны экран и одобренный ролик, а на
чистом стенде (`dev_stand.sh reset`) их нет, поэтому прогон сам заводит экран
`E2E_стенд_…` и картинку-ролик `E2E_ролик_…` (категория «служебный контент» —
одобряется без модерации) и в конце убирает **всё, что создал, — даже если
проверка упала** (плейлисты `E2E_плейлист_…` и `E2E_эфир_…` вместе с их показами
удаляются по названию; бегущие строки и шаблоны `E2E_строка_…` снимаются по метке в
тексте, до удаления экрана; состояние общего эфира возвращается). Поэтому прогон
проходит на пустой базе.

> **Осторожно: E2E — для локального стенда (§0) или стека без живых экранов.**
> Тестовые показы (завтра 10–11 ч и текущий час для «Эфира сети») и бегущая строка
> (шаг 10) прогон отправляет **только на собственный экран** `E2E_стенд_…`, а не на
> «Все экраны сети»: настоящие мини-ПК не получают их ни в ленту, ни в список закачки
> — даже если прогон оборван. **Исключение — общий эфир (шаг 9) и бегущая строка «на все
> экраны» (шаг 10), оба под `E2E_ALLOW_BROADCAST=1`: они идут на все экраны сети**,
> поэтому переменную задают только на стенде. Но прогон
> заводит в панели свои объекты (экран, ролик, плейлист, учётку рекламодателя),
> и на боевом сервере операторы увидят их в списках и журнале.
> Если прогон **оборван жёстко** (kill, таймаут docker, падение Chromium — тогда
> уборка в `finally` не выполняется), тестовые объекты остаются в панели.
> Удалите вручную по именам (все — с суффиксом `<STAMP>` — время прогона
> ЧЧММСС по UTC):
> - плейлисты `E2E_плейлист_*` и `E2E_эфир_*` — вместе с ними удаляется их показ
>   на тестовом экране (Плейлисты → 🗑, панель предупредит «стоит в N показах»);
> - общий эфир, если прогон оборвало, пока он был включён: «Эфир сети» →
>   «Выключить» (он «до следующего часа» и кончится сам, но проверьте полосу);
> - бегущая строка и шаблон `E2E_строка_*` («Бегущая строка» → «Снять» у строки и «×»
>   у шаблона); строка шла на экран `E2E_стенд_*`, а при `E2E_ALLOW_BROADCAST=1` — на
>   все экраны; она кончится сама (на 15 или 30 минут), но проверьте «Сейчас идут»;
> - ролик `E2E_ролик_*` и, если он успел загрузиться, `E2E_дубль_*` (Медиатека →
>   Общая медиатека);
> - экран `E2E_стенд_*` (Экраны); и `E2E_экран_*`, если оборвало цикл экрана.
>   Удаляйте `E2E_стенд_*` сразу: прогон шлёт за него сигнал (`POST /heartbeat/{id}`),
>   у экрана есть `last_seen`, и после жёсткого обрыва на стеке с включёнными
>   уведомлениями MAX через `offline_minutes` минут без сигналов придёт сообщение
>   «Экран … не выходит на связь»;
> - если оборвало проверку рекламодателя — учётка `e2e_adv_*` (Настройки) и
>   кабинет `E2E Рекламодатель e2e_adv_*` (Медиатека; удаляется отдельно).
> Экран `E2E_стенд_…` — не настоящий мини-ПК, на диски экранов сети ролик не попадал.

Кнопки «Просмотр» (`mprev-open`), «По датам» (`schedule-mode-dates`) и
«следующая неделя» (`schedule-week-next`) входят в белый список; слепой
прогон закрывает открывшиеся окна клавишей Esc.

Провалом считается не только упавшая проверка, но и **любая ошибка в консоли
браузера, необработанное JS-исключение или ответ HTTP ≥400** — именно так
выглядели дефекты, которые ловили руками.

### Как запускать
> Запускайте на стенде или стеке без живых экранов — см. «Осторожно» выше.

```bash
bash ui_test.sh
```

Chromium на сервер не ставится: прогон идёт в одноразовом контейнере
официального образа puppeteer, подключённом к сети стека (панель видна как
`http://nginx`). Первый запуск скачивает образ (~1 ГБ), дальше — из кеша.
Переменные: `ADMIN_USER` (по умолч. `admin`), `ADMIN_PASS` (`admin123`),
`DS_URL`, `UI_TEST_IMAGE`, `E2E_ALLOW_BROADCAST=1` (шаг «Общий эфир» и бегущая строка «на все экраны», только стенд).

На локальном стенде (§0):
```bash
ADMIN_PASS=$(cat .dev_admin_pass) DS_URL=http://nginx bash ui_test.sh                          # без шага 9 и «на все экраны»
E2E_ALLOW_BROADCAST=1 ADMIN_PASS=$(cat .dev_admin_pass) DS_URL=http://nginx bash ui_test.sh    # полный прогон
```

Ожидаемый результат — без `E2E_ALLOW_BROADCAST`:
```
 Проверок пройдено: 189, провалено: 0, ошибок в браузере: 0
```
и с `E2E_ALLOW_BROADCAST=1` (стенд, эфир до прогона выключен):
```
 Проверок пройдено: 205, провалено: 0, ошибок в браузере: 0
```
(если эфир до прогона шёл, число немного отличается: прогон его
временно выключает, а в конце возвращает прежним — это не ошибка). Код возврата `0` — можно выпускать; `1` — в выводе перечислены шаг и причина.

## Итог: чем пользоваться
| Инструмент | Уровень | Нужен живой стек | Скорость |
|---|---|---|---|
| `pytest` (server/tests) | Юнит: формулы, плейлисты, показы, дубли, бегущая строка, доступ к скачиванию и к файлам медиатеки | Нет (БД замокана) | доли секунды |
| `pytest` (agent/tests) | Юнит: код агента (повторы, `active_until`, защита очистки диска, учёт показов, очередь бегущих строк) | Нет | доли секунды |
| `smoke_test.sh` | Сквозной: API + БД + цикл эфира, лента и закачка экрана, обзор сети, бегущая строка на тестовом экране, бэкап, диагностика и файлы медиатеки только по входу (докачка экрана — Range через nginx), общий эфир со сроком (на стенде, `SMOKE_ALLOW_BROADCAST=1`) | Да | секунды |
| `ui_test.sh` | Интерфейс: разделы, кнопки, плейлист «окно → показ → карточка → расписание», «Эфир сети» (таблица, панель, общий эфир — на стенде, `E2E_ALLOW_BROADCAST=1`), бегущая строка на тестовом экране («на все экраны» — только со `E2E_ALLOW_BROADCAST=1`), «Скачать» бэкапа и архива диагностики с входом, файлы медиатеки (без входа 401, кадр, миниатюра и «Скачать» по cookie) | Да | ~2 минуты |
| `dev_stand.sh` | Локальный стенд для всего вышеперечисленного | — | `up` ~минуты |

Полноценная проверка перед релизом — **все уровни**: сначала `pytest` сервера и
агента (быстро ловят регресс в логике), затем `smoke_test.sh` (живая система
отрабатывает цикл целиком), затем `ui_test.sh` (панель кликается и не сыплет
ошибками). Разработчику — всё это на локальном стенде `dev_stand.sh`. На боевом
сервере с живыми экранами запускайте **`smoke_test.sh`** (он создаёт только свои
`SMOKE_…` объекты на собственном тестовом экране); **`ui_test.sh` — не на боевом
сервере**, а на стенде или стеке без настоящих экранов (см. предупреждение в §3).
