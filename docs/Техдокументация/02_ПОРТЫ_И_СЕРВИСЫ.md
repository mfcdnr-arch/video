# 02. Порты и сервисы

Всё по `docker-compose.yml` и `nginx.conf`. Имена контейнеров фиксированы
(`container_name`), поэтому команды `docker exec ds_api …` стабильны.

## Контейнеры и порты

| Контейнер | Образ | Внутр. порт | Порт на хосте | Назначение |
|---|---|---|---|---|
| **ds_nginx** | `nginx:alpine` | 80 | **80/tcp** ✅ | Веб-панель, прокси API/WS, раздача медиа |
| **ds_ntp** | `./ntp` (chrony) | 123/udp | **123/udp** ✅ | Раздача точного времени мини-ПК |
| **ds_api** | `./server` | 8000 | — (внутр.) | FastAPI, вся логика |
| **ds_postgres** | `postgres:15-alpine` | 5432 | — (внутр.) | База данных |
| **ds_redis** | `redis:7-alpine` | 6379 | — (внутр.) | Брокер Celery |
| **ds_minio** | `minio/minio:latest` | 9000 / 9001 | — (внутр.) | Хранилище бэкапов медиа (API/консоль) |
| **ds_celery** | `./server` | — | — | Worker + Beat (фоновые задачи) |

✅ = проброшено наружу. Остальные доступны **только** внутри Docker-сети — это
осознанное решение по безопасности (см. [архитектуру](01_АРХИТЕКТУРА.md#границы-безопасности)).

> Итого наружу открыты только **80/tcp** и **123/udp**. Их и нужно разрешить в
> firewall между сервером и сегментом мини-ПК.

## Маршруты nginx (порт 80)

| Путь | Куда | Назначение |
|---|---|---|
| `/` | статика `/usr/share/nginx/panel` | Веб-панель администратора (SPA) |
| `/api/` | `http://api:8000/` | REST API (лимит тела **2G**, таймаут 300 c) |
| `/ws/` | `http://api:8000/ws/` | WebSocket дашборда (таймаут 86400 c) |
| `/api/ws/*` | `http://api:8000/` | WebSocket-команды агентам |
| `/media/` | том `/data/media/` | Скачивание видео мини-ПК (Range/докачка) |
| `/health` | `http://api:8000/health` | Проба здоровья API |
| `/docs`, `/openapi.json` | `http://api:8000/…` | Swagger UI (только из локальной сети) |
| `/token` | `http://api:8000/token` | Авторизация (в т.ч. для Swagger) |

## Тома

| Том | Монтируется в | Содержимое |
|---|---|---|
| `postgres_data` | ds_postgres:/var/lib/postgresql/data | База данных |
| `media_data` | ds_api, ds_celery (rw); ds_nginx (ro) | Медиафайлы |
| `minio_data` | ds_minio:/data | Бэкапы медиа |
| `backup_data` | ds_api, ds_celery:/data/backups | Дампы БД |
| `agent_updates_data` | ds_api, ds_celery:/data/agent_updates | Пакеты OTA |
| `nginx_logs` | ds_nginx:/var/log/nginx | Логи nginx |

## Переменные окружения (`.env`)

| Переменная | Назначение | Где задаётся |
|---|---|---|
| `POSTGRES_DB` | Имя БД (`display_system`) | install_server.sh |
| `POSTGRES_USER` | Пользователь БД (`display_user`) | install_server.sh |
| `DB_PASSWORD` | Пароль БД (**секрет**) | генерируется |
| `MINIO_USER` | Пользователь MinIO | install_server.sh |
| `MINIO_PASSWORD` | Пароль MinIO (**секрет**) | генерируется |
| `SECRET_KEY` | Подпись токенов входа (**секрет**) | генерируется |
| `BACKUP_KEEP` | Сколько дампов БД хранить (опц., дефолт в коде) | опц. |
| `ARCHIVE_AFTER_DAYS` | Когда архивировать `play_log` (опц.) | опц. |

Внутренние URL (задаются в compose, не в `.env`):
`DATABASE_URL=postgresql://…@postgres:5432/…`, `REDIS_URL=redis://redis:6379`,
`MEDIA_PATH=/data/media`, `BACKUP_DIR=/data/backups`, `AGENT_UPDATE_PATH=/data/agent_updates`.

Шаблон всех переменных — в [`.env.example`](../../.env.example).

## Healthcheck'и
| Сервис | Проверка | Интервал |
|---|---|---|
| ds_postgres | `pg_isready` | 10 c, 5 попыток |
| ds_redis | `redis-cli ping` | 10 c, 5 попыток |
| ds_api | `curl /health` | 15 c, старт-период 30 c, 5 попыток |

`api` стартует только после `postgres` и `redis` (healthy); `nginx` — после
`api` (healthy).

## Плеер и локальные сокеты мини-ПК (агент)
| Ресурс | Назначение |
|---|---|
| `/tmp/ds-mpv.sock` (unix-сокет) | IPC-управление плеером mpv (JSON-команды) |
| путь плеера | `player_bin` в `config.ini` (по умолчанию `/usr/bin/mpv`) |

Плеер — **mpv**, управляется через локальный Unix-сокет (не TCP-порт). Наружу
мини-ПК **ничего не слушает** — только исходящие соединения к серверу
(HTTP :80, WebSocket, NTP :123).

## Полезные команды
```bash
docker compose ps                       # статусы всех контейнеров
docker compose logs -f api              # логи API
docker exec ds_api curl -sf localhost:8000/health   # здоровье изнутри
docker exec ds_postgres pg_isready -U display_user  # БД жива
docker exec ds_ntp chronyc tracking     # синхронизация времени
docker stats --no-stream                # потребление ресурсов
```
