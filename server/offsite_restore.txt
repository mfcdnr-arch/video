=========================================================

Копия:          {{copy_file}}
Создана:        {{created_at}} (МСК)
Кто скачал:     {{created_by}}
Адрес сервера:  {{host}}
Версия базы:    миграция {{migration}}

Этот файл написан для человека, который систему не знает. Идите по шагам,
по порядку, ничего не пропуская. Каждую команду можно копировать целиком и
вставлять в терминал (в терминале вставка - Ctrl+Shift+V), затем Enter.
Если старый сервер сломан - это нормально: всё нужное уже есть на флешке,
сам старый сервер для восстановления не нужен.


ЧТО ВНУТРИ КОПИИ
----------------
Копия заперта паролем (файл copy.tar.gz.enc). Внутри неё: программа сервера
вместе с файлом .env (пароли и ключи сервера), свежий дамп базы данных,
документы рекламодателей, папка «Документы» медиатеки, файлы обновления
экранов и MANIFEST.txt (опись: что внутри, контрольные числа из базы).
Сами ролики (видео) в эту копию НЕ входят: они лежат на флешке отдельными
файлами ds_media_*.tar.


ШАГ 1. ЧТО ПОНАДОБИТСЯ
----------------------
 а) Флешка с файлом {{copy_file}} и ВСЕМИ файлами ds_media_*.tar.
    Флешка должна быть exFAT или NTFS. На FAT32 файл больше 4 ГБ не
    записывается, архивы роликов на ней не поместятся. Если Linux не
    открывает флешку exFAT, поставьте пакет exfat-fuse:
        sudo apt install exfat-fuse
    и вставьте флешку заново.
 б) Пароль на копию. Его знает владелец системы, на флешке он не записан.
    Без него копию не откроет никто. Копия открывается тем паролем, который
    действовал в день её создания.
 в) Новая машина с Linux (Astra Linux 1.7 или похожий), интернет, Docker с
    Compose v2. Проверьте:
        docker --version
        docker compose version
        docker info
    Если «docker info» отвечает «permission denied», добавляйте sudo в начало
    каждой команды docker и команды bash install_server.sh ниже.
    Нужно свободное место - примерно втрое больше размера всех файлов на
    флешке. Порт 80 на машине должен быть свободен.
 г) Сетевой адрес новой машины ДОЛЖЕН СОВПАДАТЬ со старым: {{host}}.
    Он прописан на всех экранах (мини-ПК), и они ищут сервер именно по нему.
    Задайте на новой машине тот же IP-адрес (если выше имя, а не цифры -
    направьте это имя на новую машину). Старый сервер к этому моменту должен
    быть выключен, иначе у двух машин будет один адрес.


ШАГ 2. ОТКРЫТЬ КОПИЮ
--------------------
Вставьте флешку. Откройте в файловом менеджере папку флешки, где лежит файл
{{copy_file}}, и запустите в ней терминал (правая кнопка мыши, «Открыть
терминал»). Или вручную: команда «ls /media/$USER» покажет название флешки,
затем перейдите в неё: cd "/media/$USER/НАЗВАНИЕ_ФЛЕШКИ" (кавычки нужны,
если в названии есть пробелы).

Создайте рабочую папку на диске новой машины (не на флешке) и распакуйте в
неё внешний архив:

    mkdir -p ~/ds_restore
    tar -xf {{copy_file}} -C ~/ds_restore
    cd ~/ds_restore
    ls

Должны быть три файла: ВОССТАНОВЛЕНИЕ.txt (этот), copy.tar.gz.enc и
copy.tar.gz.enc.sha256. Проверьте, что файл не испортился при копировании:

    sha256sum -c copy.tar.gz.enc.sha256 && echo "ФАЙЛ ЦЕЛЫЙ" || echo "ФАЙЛ ПОВРЕЖДЁН"

Нужна надпись «ФАЙЛ ЦЕЛЫЙ». Если «ФАЙЛ ПОВРЕЖДЁН» - скопируйте файл с флешки
ещё раз; не помогло - берите копию за предыдущий день.

Снимите пароль. Команда спросит пароль на копию; при вводе на экране ничего
не появляется - это нормально. Введите пароль и нажмите Enter:

    {{decrypt_cmd}}

Если появилось «bad decrypt» - пароль неверный. Если «No such file» - вы не
в папке ~/ds_restore (выполните cd ~/ds_restore).

Распакуйте открытый архив:

    mkdir copy
    tar -xzf copy.tar.gz -C copy
    rm copy.tar.gz
    ls copy

В папке copy должно быть: program, db, documents, media_documents,
agent_updates и MANIFEST.txt. Прочитать опись:

    cat copy/MANIFEST.txt


ШАГ 3. ПОСТАВИТЬ ПРОГРАММУ СЕРВЕРА
----------------------------------
Программа лежит в copy/program вместе с настоящим файлом .env (пароли и
ключи старого сервера). Поэтому установщик не создаёт новых паролей и
ничего менять не нужно. Переложите папку на постоянное место и запустите
установку (нужен интернет, идёт несколько минут):

    mv ~/ds_restore/copy/program ~/digital-signage
    cd ~/digital-signage
    bash install_server.sh

В конце установщик пишет «Установка завершена» или перечисляет ошибки (строки
с ✗). В конце он может написать «Вход: admin / admin123» - это подсказка
для чистой установки, к вам она не относится: после шага 4 войти нужно со
СВОИМ прежним паролем.

Папку ~/digital-signage не удаляйте и не переносите: в ней живёт сервер.
Все команды этой инструкции выполняйте под одним и тем же пользователем.


ШАГ 4. ВЕРНУТЬ БАЗУ ДАННЫХ
--------------------------
Сейчас сервер поднят с пустой базой. Остановите программу, пересоздайте
базу, залейте в неё дамп из копии и запустите программу обратно:

    cd ~/digital-signage
    docker compose stop api celery
    docker exec ds_postgres psql -U {{pg_user}} -d postgres -c "DROP DATABASE {{pg_db}}" -c "CREATE DATABASE {{pg_db}} OWNER {{pg_user}}"
    gunzip -c ~/ds_restore/copy/db/backup_*.sql.gz | docker exec -i ds_postgres psql -U {{pg_user}} -d {{pg_db}} -q
    docker compose start api celery

Подождите около 30 секунд и проверьте, что сервер отвечает:

    docker exec ds_api curl -s http://localhost:8000/health

Ответ должен начинаться с {"status":"ok".


ШАГ 5. ВЕРНУТЬ ФАЙЛЫ
--------------------
Документы рекламодателей, файлы обновления экранов и «Документы» медиатеки:

    docker cp ~/ds_restore/copy/documents/. ds_api:/data/backups/documents/
    docker cp ~/ds_restore/copy/agent_updates/. ds_api:/data/agent_updates/
    docker cp ~/ds_restore/copy/media_documents/. ds_api:/data/media/

Ролики. На флешке их несколько архивов ds_media_*.tar («новые» и «все»).
Распаковать нужно ВСЕ архивы, в одну и ту же папку: имена файлов не
повторяются, поэтому они складываются вместе. Откройте терминал в папке
флешки, где лежат ds_media_*.tar (как в шаге 2), и выполните:

    ls ds_media_*.tar
    mkdir -p ~/ds_restore/media_all
    for f in ds_media_*.tar; do tar --exclude=media/MANIFEST_media.txt -xf "$f" -C ~/ds_restore/media_all; done
    docker cp ~/ds_restore/media_all/media/. ds_api:/data/media/

Убедитесь, что «ls» показал все архивы роликов, которые вы ожидали. Если
архивов роликов у вас нет, этот абзац пропустите: ролики придётся загрузить
в панель заново.


ШАГ 6. ПРОВЕРКА
---------------
 1) Откройте в браузере http://{{host}}/ (на самой новой машине можно
    http://localhost/) и войдите со своим прежним логином и паролем.
 2) Сверьте контрольные числа. Эта команда печатает числа из базы:

    docker exec ds_postgres psql -U {{pg_user}} -d {{pg_db}} -x -c "{{counts_sql}}"

    Сравните их с блоком «Контрольные числа» в MANIFEST.txt:
        cat ~/ds_restore/copy/MANIFEST.txt
    Числа должны совпасть. Расхождение на единицу-две возможно, если сервер
    успел поработать; большое расхождение значит, что шаг 4 не удался.
 3) Раздел «Экраны»: экраны выходят на связь сами, обычно в течение нескольких
    минут, если адрес сервера прежний ({{host}}).
 4) Медиатека: ролики на месте. Миниатюры создаются заново при первом
    просмотре, это нормально.
 5) Старые резервные копии базы (Настройки, «Резервное копирование») и архивы
    диагностики экранов в списках будут показаны без файлов: они остались на
    старом сервере. Это нормально. Новые создаются как обычно, а ночная копия
    роликов (MinIO) заполнится сама.


ШАГ 7. УБРАТЬ ЗА СОБОЙ
----------------------
В папке ~/ds_restore лежат пароли сервера в открытом виде. Когда убедитесь,
что всё работает, удалите её:

    rm -rf ~/ds_restore

Папку ~/digital-signage не удаляйте: это сервер. Саму флешку с копией храните
отдельно от пароля на копию.


ЕСЛИ ЧТО-ТО НЕ ПОЛУЧИЛОСЬ
-------------------------
 - Установщик остановился на ошибке: под строкой с ✗ или «ОСТАНОВ» он пишет
   подсказку (строка с «└─»). Полный лог: ~/digital-signage/install_server.log.
 - При DROP DATABASE написано «is being accessed by other users»: снова
   выполните docker compose stop api celery, подождите 10 секунд и повторите
   команду DROP DATABASE.
 - Вход в панель не принимает прежний пароль: проверьте, что шаг 4 выполнен
   до конца (до него в базе нет ваших пользователей).
 - Ничего не помогло: соберите диагностику командой
       cd ~/digital-signage && bash collect_diag.sh
   и вместе с текстом ошибки передайте тому, кто поддерживает систему.
