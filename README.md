## Быстрый старт

### Шаг 1: Перейдите в каталог проекта
```bash
cd Video_miniPC_v16.2_modular
```

### Шаг 2: Запустите сервер
```bash
bash install_server.sh
```
Скрипт сам создаст `.env` со случайными секретами (пароль БД, пароль MinIO,
SECRET_KEY для подписи токенов), соберёт контейнеры и дождётся готовности API.
Миграции БД применяются автоматически при первом старте Postgres.

Повторный запуск безопасен: существующий `.env` не перезаписывается
(пароли и ключи сохраняются), контейнеры просто обновляются.

**При первой установке пароль администратора генерируется случайным** и
печатается в конце работы `install_server.sh` — запишите его. При первом входе
(логин `admin`) панель потребует задать новый пароль.

Веб-панель доступна на порту 80 (nginx): `http://10.0.119.100/`.

### Шаг 3: Установите агент на мини ПК
Из корня проекта (скрипт `install.sh` лежит рядом с `install_server.sh`):
```bash
sudo bash install.sh http://10.0.119.100 YOUR_TOKEN 1 toor
```
Аргументы: URL сервера, токен устройства, ID экрана, пользователь X-сессии
(по умолчанию `toor`).

## Что нового в v16.2

✅ Модульный сервер: монолитный `main.py` разнесён на роутеры в `server/routers/` (сейчас 20),
`main.py` теперь только собирает приложение  
✅ Каталоги переименованы: `app/` → `server/`, `client/` → `agent/`;
инсталлятор агента `install.sh` перенесён в корень проекта  
✅ Аутентификация агентов по токену устройства (заголовок `X-Token`)  
✅ WebSocket-push команд агентам в реальном времени (`ws_manager.py`, роутер `websockets`)  
✅ Биллинг: тарифы рекламодателей и отчёты (`routers/billing.py`, миграция `017_billing.sql`)  
✅ OTA-обновление агентов (`routers/agent_ota.py`, `agent/ds_ota_updater.py`)  
✅ Плейлист = эфирный блок фиксированной длины (по умолчанию 60 мин, максимум):
свободное время равномерно добивается заглушками из папки «Заглушки»,
с предупреждениями о нехватке; произвольный режим отключаем
(`fill_to_hour`/`target_seconds`, отчёт `/reports/fillers`)  
✅ Общая медиатека: ролики и папки без привязки к рекламодателю; в плейлисте
выбор ролика по папкам (`/media/common`, `/media/folders-all`)  
✅ Самодиагностика: панель → Настройки → «Диагностика сервера»
(`GET /system/selfcheck`) + автолечение на хосте `selfheal.sh`
(упавшие контейнеры, рестарт-цикл ntp, «чёрная панель» из-за nginx)  
✅ Бегущая строка — срочные объявления на сегодня (миграция 034): одна страница
«Сейчас идут» + конструктор + шаблоны; срок «до снятия» / «до ЧЧ:00 сегодня» /
«на N минут»; «где» — все экраны / группы / выбранные экраны (определяется в момент
показа); несколько строк на экране идут по очереди. Строку знает сервер: агент 1.4.0
берёт её из ленты экрана (поле `tickers`), переживает перезагрузку мини-ПК, смену
плейлиста и «Стоп» (на остановленном экране не видна, после «Показ» бежит дальше) и
сам снимает по сроку; в heartbeat шлёт `ticker_state`, поэтому панель показывает
«бежит на X из N» и причину по каждому экрану. Старые агенты (< 1.4.0) получают
строку командами `ticker_show` / `ticker_hide`. Эндпоинты: `GET /tickers/overview`
(всё для страницы одним ответом), `GET/POST /tickers`, `PUT/DELETE /tickers/{id}`,
`GET/POST /ticker-templates`, `PUT/DELETE /ticker-templates/{id}`; снятие по сроку —
Celery `expire_tickers` (раз в минуту, запись «Бегущая строка снята по сроку»).
Модули `ticker_rules.py`, `ticker_store.py`, `routers/ticker.py`  
✅ Отчёты: у каждой таблицы свой фильтр по строкам и сортировка кликом
по заголовку столбца; фильтр по **дню недели** и столбец «День» в журнале
показов и выгрузках; все даты в панели — с днём недели  
✅ Кнопка «🧾 Диагностика» экрана: агент по команде собирает архив логов и
присылает на сервер, панель даёт скачать (миграция 027)  
✅ Бэкап БД и архивы диагностики скачиваются только после входа в панель
(бэкап — администратору и супер-администратору); без входа и по токену экрана — 401  
✅ Файлы медиатеки (ролики, документы, миниатюры, `/media/<имя>`) — тоже только по
входу: без входа 401 на любой номер; агент качает по `X-Token` только одобренные
ролики, с докачкой по Range (файл отдаёт nginx через `X-Accel-Redirect`); панель —
по httpOnly-cookie `ds_media` (`media_access.py`)  
✅ Контроль часов хоста: смещение видно в самодиагностике и selfheal.sh
(с командой лечения)  
✅ Контроль подключения монитора: агент читает `/sys/class/drm/*/status` и шлёт
признак в heartbeat; в панели бейдж 📺 у экрана и блок «Монитор не подключён»
на дашборде, в MAX — уведомление (миграция 028). Ловит отсоединённый кабель
HDMI/DisplayPort, когда мини-ПК «онлайн и играет», а на мониторе пусто  
✅ Раздел «Рекламодатели»: карточка одного рекламодателя — объёмы и доля эфира,
тепловая карта «день × час», сырой журнал выходов (proof of play), качество
доставки (простои экранов и часы без монитора), ролики со статусом модерации
38-ФЗ и сроком хранения материалов (`routers/advertiser_office.py`,
миграция `029_advertiser_office.sql`). Контакты/охват намеренно не считаются —
только доказуемый факт  
✅ Кабинет рекламодателя: роль `advertiser` с серверной изоляцией (кабинет
заводится автоматически при создании пользователя), «сейчас в эфире»,
уведомления (модерация, сроки, счета), свой экспорт журнала выходов в Excel,
сравнение с прошлым периодом  
✅ Документы: реквизиты исполнителя (Настройки, УСН), договоры с произвольным
расчётным периодом, генерация **эфирной справки, акта и сводного отчёта**
(PDF/Excel) с реестром — повторное скачивание отдаёт тот же файл; дебиторка,
история изменений тарифа, заметки по клиенту  
✅ Медиатека: владельцу контента при регистрации автоматически заводятся папки
«Видеореклама» и «Документы» (сканы договоров и деклараций, `status='document'` —
в эфир не выдаются и в плейлист не добавляются); кнопка «+ Госорганы» заводит
владельца **без биллинга** (миграция 030): тарифа нет, счета не выставляются  
✅ Показы по датам: плейлист на выбранные экраны, даты и целые часы («Куда и
когда»), решения по пересечениям, «Расписание → По датам»
(`routers/placements.py`, `placements_logic.py`, миграция 031)  
✅ «Эфир сети»: обзор сети в реальном времени — на каждом экране что идёт сейчас,
какой ролик играет и что дальше (`GET /network/live`, `routers/network.py`,
`network_live.py`); панель «О плейлисте» и правка плейлиста поверх страницы;
общий эфир включается осознанно — «до отмены» или «до ЧЧ:00 сегодня», кончается
сам (Celery `expire_broadcast`, журнал операций), файлы его плейлиста качаются
экранами заранее (`broadcast_rules.py`, `broadcast_store.py`, миграция 032)  
✅ Единое правило «в сети»: последний сигнал экрана не старше 5 минут
(`screen_online.py`) — одинаково в «Экранах», Дашборде, «Эфире сети»,
«Бегущей строке» и «Обновлении агентов»; «не в сети X ч Y мин» /
«ни разу не выходил на связь»

## Проверка после установки

### На сервере
```bash
cd Video_miniPC_v16.2_modular
docker compose ps                    # все 7 контейнеров должны быть running
curl http://localhost/health         # 200 OK
docker exec ds_ntp chronyc sources   # NTP видит российские серверы времени
```
Затем откройте панель в браузере: `http://10.0.119.100/`.

Перед релизом — три уровня проверки (подробно: `docs/Техдокументация/04_ТЕСТЫ.md`):
```bash
bash run_tests.sh    # pytest: биллинг/кампании, плейлисты, показы, общий эфир, бегущая строка, обзор сети, контроль монитора
bash smoke_test.sh   # API и цикл «экран → медиа → плейлист → расписание»
                     #   (SMOKE_ALLOW_BROADCAST=1 — ещё и шаг «Общий эфир»: на ВСЕ экраны, только на стенде)
bash ui_test.sh      # браузерный прогон панели (на стенде/без живых экранов: заводит тестовые объекты E2E_…)
                     #   (E2E_ALLOW_BROADCAST=1 — ещё и включение общего эфира и бегущая строка «на все экраны»: на ВСЕ экраны, только на стенде)
```

### На мини ПК
```bash
systemctl status ds-agent            # active (running)
journalctl -u ds-agent -f            # логи в реальном времени
pgrep -a mpv                         # процесс должен быть запущен
```

## Полное удаление и переустановка

**⚠️ Смотрите `docs/CLEANUP_FULL_2026-07-01.md` для полных инструкций**

Быстро:
```bash
# Удалить сервер (из каталога проекта; -v удаляет тома с БД и медиа!)
docker compose down -v

# Удалить мини ПК
sudo systemctl stop ds-agent
sudo systemctl disable ds-agent
sudo rm -rf /opt/ds-agent /etc/ds-agent /var/log/ds-agent
sudo rm -f /etc/systemd/system/ds-agent.service
sudo systemctl daemon-reload
```
